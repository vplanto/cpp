# Лекція 7: Посилання (References) та передача параметрів у функції

## 🏁 Експрес-опитування

У лекції 6 ми "гралися з вогнем" — вказівниками. Давайте перевіримо, чи ми засвоїли ключові ідеї, перш ніж перейти до безпечнішої альтернативи.

1.  Якщо `int x = 10;`, що поверне вираз `&x`?
2.  Якщо `int *ptr = &x;`, що поверне вираз `*ptr`?
3.  Яка головна небезпека "неініціалізованого" вказівника (напр., `int *p; *p = 10;`)?
4.  Який символ ми рекомендуємо використовувати для "нульових" вказівників у сучасному C++ (`0`, `NULL` чи `nullptr`)?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  Оператор `&` поверне **адресу** змінної `x` у пам'яті (наприклад, `0x7ffc...`).
2.  Оператор `*` (розіменування) поверне **значення**, що лежить за адресою, тобто `10`.
3.  **Невизначена поведінка (Undefined Behavior)**. Вказівник `p` вказує на випадкову адресу ("сміття"), і ми намагаємося записати `10` у цю випадкову комірку, що може "зламати" програму.
4.  **`nullptr`**. Це ключове слово, спеціально створене для цього, воно безпечніше і чіткіше.

</details>

## Що таке посилання (Reference)?

**Посилання (Reference)**, яке з'явилося в C++, — це **псевдонім (alias)** або альтернативне ім'я для *вже існуючої* змінної. Після створення посилання ви можете звертатися до однієї і тієї ж комірки пам'яті, використовуючи як оригінальне ім'я, так і ім'я-псевдонім.

> [!TIP]
> ### Життєва аналогія: паспортне ім'я та прізвисько
> Уявіть студента: за паспортом він *Олександр*, а друзі кличуть його *Сашко*. Скільки тут фізичних людей? **Одна людина**.
> Якщо *Сашко* отримає оцінку — оцінку отримає *Олександр*. Посилання в C++ працює точно так само: це не окрема комірка зі значенням, це ще одна табличка на тих самих дверях пам'яті.

Основне призначення посилань — використання в якості параметрів функцій для реалізації механізму **передачі за посиланням (pass-by-reference)** та повернення результатів без копіювання.

### Що таке посилання «під капотом» (Under the Hood)?

Для компілятора та апаратного забезпечення посилання — це не містика. 

> **Апаратна сутність:** На рівні компілятора посилання зазвичай реалізується як **константний вказівник (`Type * const`), який компілятор автоматично розіменовує при кожному зверненні**.

Погляньте на повну еквівалентність логіки:

```cpp
int a = 10;

// Синтаксис C++ (посилання):
int& ref = a;
ref = 20;            // звертаємося напряму як до змінної

// Як компілятор реалізує це «під капотом» через вказівник:
int* const ptr = &a; // адреса зафіксована назавжди
*ptr = 20;           // авто-розіменування кожного разу
```

Завдяки цьому ми отримуємо **всі переваги вказівників (робота безпосередньо з пам'яттю оригіналу), але без небезпеки помилитися з зірочками `*`, амперсандами `&` або потрапити на `nullptr`**.

### Подвійне значення символу `&`

Символ `&` в C++ має два принципово різних значення залежно від **контексту** (див. детальну шпаргалку в кінці [Лекції 06](06_pointers.md#шпаргалка-символи--та--у-різних-контекстах)):

* **В оголошеннях (у типі даних):** Оголошує **посилання**. `int &refNumber = number;` (refNumber — це псевдонім).
* **У виразах (перед змінною):** Оператор **отримання адреси**. `&number` повертає числову адресу комірки пам'яті.

**Синтаксис оголошення:**

```cpp
// newName стає новим ім'ям (псевдонімом) для existingName
type &newName = existingName;

// Приклад:
int number = 10;
int &refNumber = number; // refNumber - це тепер інше ім'я для 'number'

refNumber = 20; // Це змінює 'number' на 20
cout << number; // Виведе 20
```

## Посилання проти вказівників

Хоча посилання та вказівники під капотом оперують адресами, на рівні мови між ними є принципові відмінності:

| Критерій | Вказівник (`*`) | Посилання (`&`) |
| :--- | :--- | :--- |
| **Ініціалізація** | Може бути неініціалізованим (вказувати у сміття). Можна ініціалізувати `nullptr`. | **Обов'язково** має бути ініціалізоване реальною змінною при створенні. |
| **Зміна адреси** | Може бути перенаправлений на іншу комірку (`ptr = &another;`). | **Неможливо переприв'язати.** Воно намертво прив'язане до своєї змінної. |
| **Синтаксис доступу** | Потребує **явного розіменування** через `*` (`*ptr = 10;`). | Працює як звичайна змінна: розіменовується **автоматично**. |
| **Null-безпека** | Може бути `nullptr`. Потребує перевірки `if (ptr != nullptr)`. | **Не може бути `null`**. Гарантовано дивиться на валідний об'єкт. |
| **Арифметика** | Підтримує адресну арифметику (`ptr++`, `ptr + 5`). | Арифметики посилань **не існує** (додавання змінює саме значення). |

### ❓ Питання до групи

Чому творці C++ додали посилання, якщо вже були вказівники?

<details markdown="1">
<summary>Натисніть, щоб побачити відповідь</summary>
Вони вирішували дві фундаментальні проблеми:

1. **Безпека:** Посилання не можуть бути `nullptr` і не можуть бути неініціалізованими. Це усуває 90% типових збоїв пам'яті.
2. **Чистота коду:** Запис `ref = 10;` набагато читабельніший за `*ptr = 10;`. Особливо це критично при перевантаженні операторів (наприклад, `cin >> x;` було б жахливим, якби вимагало `cin >> &x;`).
</details>

## Передача параметрів у функції

Це головне практичне призначення посилань.

### Мотивація: як повернути більше одного значення?
Оператор `return` у C++ повертає лише **одне** значення. Що робити, якщо функція має повернути два або три результати?
Наприклад, ділення з остачею (частка і остача):

```cpp
// За допомогою посилань реалізуються "вихідні параметри" (out-parameters):
void divide(int dividend, int divisor, int& quotient, int& remainder) {
    quotient = dividend / divisor;
    remainder = dividend % divisor;
}

int main() {
    int q, r;
    divide(17, 5, q, r);
    cout << "Частка: " << q << ", Остача: " << r << endl; // 3 і 2
}
```

---

### Три способи передачі аргументів

#### 1. За значенням (Pass-by-Value)
* **Що відбувається:** Створюється повна **копія** даних у стековому кадрі викликаної функції.
* **Ефект:** Зміни всередині функції відбуваються з копією і **не зачіпають оригінал**.
* **Коли використовувати:** Для простих базових типів (`int`, `double`, `char`, `bool`).
* **Недолік:** Вкрай повільно для великих об'єктів (довгі рядки, масиви, структури).

#### 2. За вказівником (Pass-by-Pointer) — *Спадщина мови C*
* **Що відбувається:** Передається копія адреси.
* **Синтаксис:** Потребує `*` у функції та `&` при виклику: `func(&myVar)`.
* **Коли використовувати:** Тільки коли аргумент може бути відсутній (дозволено передати `nullptr`).

#### 3. За посиланням (Pass-by-Reference) — *Ідіоматичний C++*
* **Що відбувається:** Створюється псевдонім (без копіювання!). Функція працює безпосередньо з пам'яттю оригіналу.
* **Синтаксис:** Чистий, як при передачі за значенням: `func(myVar)`.
* **Коли використовувати:** Коли функція повинна змінити передану змінну (out-параметри).

## Безпека та ефективність: `const Type&`

Ключове слово `const` у комбінації з посиланнями формує одне з найважливіших правил розробки на C++.

```cpp
void printMessage(const std::string& message);
```

Цей запис декларує: *«Я передаю об'єкт за посиланням, щоб **не витрачати час і пам'ять на копіювання**, але гарантую, що **не змінюватиму його** (`const`)»*.

### ⚡ Критична властивість: прив'язка до rvalue (літералів та виразів)

У початківців часто виникає питання: чому не використовувати звичайне `Type&` завжди?

> [!WARNING]
> **Неконстантне посилання (`Type&`) НЕ МОЖЕ прив'язуватися до констант і тимчасових значень (літералів)!**

Подивіться на різницю:

```cpp
void badPrint(int& x) {
    cout << x << endl;
}

void goodPrint(const int& x) {
    cout << x << endl;
}

int main() {
    int val = 10;
    badPrint(val);   // OK
    
    // badPrint(42);     // ПОМИЛКА КОМПІЛЯЦІЇ! 42 — це тимчасовий літерал (rvalue).
    // badPrint(val + 5);// ПОМИЛКА КОМПІЛЯЦІЇ! Результат виразу — тимчасовий об'єкт.

    goodPrint(42);      // OK! Скомпілюється ідеально.
    goodPrint(val + 5); // OK! Скомпілюється ідеально.
}
```

**Чому так?**
Стандарт C++ забороняє прив'язувати неконстантні lvalue-посилання до тимчасових об'єктів, щоб захистити вас від логічних помилок (зміна тимчасового значення не має сенсу).
Але для **константного посилання (`const Type&`)** компілятор робить особливий виняток: він створює анонімну тимчасову змінну і **подовжує її час життя** на період виконання виклику.

> [!TIP]
> **Золоте правило архітектури функцій у C++:**
> 1. Базові типи (`int`, `double`, `char`, `bool`) передавайте **за значенням** (`int x`).
> 2. Складні об'єкти (`string`, `vector`, класи, структури), які не потрібно змінювати, передавайте **за константним посиланням** (`const string& s`).
> 3. Змінні, які функція повинна змінити як результат своєї роботи, передавайте **за неконстантним посиланням** (`int& outResult`).

## Зведена матриця: вибір способу передачі аргументів

| Спосіб передачі | Синтаксис | Чи відбувається копіювання? | Чи може змінити оригінал? | Чи приймає вирази та літерали (`42`, `a + b`)? | Рекомендований сценарій |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **За значенням (by value)** | `void f(int x)` | Так | Ні | Так | Малі типи (1–8 байт): `int`, `double`, `char`, `bool` |
| **За неконстантним посиланням** | `void f(int& x)` | **Ні** | **Так** | ❌ **Ні** | Вихідні параметри функції (out-параметри) |
| **За константним посиланням** | `void f(const Big& x)` | **Ні** | Ні | **Так** | Усі великі типи: `string`, структури, об'єкти (Read-Only) |
| **За вказівником** | `void f(int* x)` | Копія адреси (8 байт) | **Так** | ❌ (потрібен `&` або вказівник) | Опціональні параметри (де допустимий `nullptr`) |

## Повернення значень за посиланням

Функції можуть не лише приймати, але й повертати посилання (`int& func()`). Це дозволяє використовувати виклик функції у лівій частині оператора присвоєння (lvalue), що є фундаментальним для роботи перевантажених операторів (наприклад, оператора індексації масиву `[]`).

```cpp
int arr[5] = {10, 20, 30, 40, 50};

int& getElement(int index) {
    return arr[index]; // повертаємо посилання на глобальний елемент масиву
}

int main() {
    getElement(2) = 999; // Змінює arr[2] на 999!
    cout << arr[2];      // 999
}
```

### ⚠️ Критична помилка: висячі посилання (Dangling Reference) та стек

> **Категорично заборонено повертати посилання на локальну змінну функції!**

Згадаймо [Карту пам'яті процесу](06_pointers.md#карта-оперативної-памяті-процесу-memory-layout) з попередньої лекції:

```text
Стек під час виклику badFunction():
| ...                 |
| [localVar = 10]     | <-- Стековий кадр badFunction (Stack Frame)
+---------------------+
Після виконання return:
Стековий кадр ЗНИЩУЄТЬСЯ (покажчик стека зміщується, пам'ять звільняється).
Посилання продовжує вказувати на цю вже мертву область пам'яті!
```

```cpp
// КРИТИЧНО ПОГАНИЙ КОД:
int& badFunction() {
    int localVar = 10;
    return localVar; // Повернення посилання на змінну зі стека, яка зараз зникне!
}

int main() {
    int& ref = badFunction(); // 'ref' є висячим посиланням (Dangling Reference)
    // ref вказує на сміття або пам'ять, яка перезапишеться наступним викликом будь-якої функції!
    cout << ref << endl; // Невизначена поведінка (Undefined Behavior)
}
```

## Контрольні питання

1.  **Концепція.** Назвіть дві ключові відмінності між вказівником та посиланням в C++.
2.  **Застосування.** Що таке "передача за посиланням" (pass-by-reference)? Які переваги вона дає порівняно з "передачею за значенням" (pass-by-value), особливо при роботі з великими об'єктами?
3.  **Аналіз коду.** Знайдіть критичну логічну помилку в наступній функції. Поясніть, чому цей код небезпечний.
    ```cpp
    int& getSomeValue() {
        int temp = 5;
        // ... якісь обчислення ...
        return temp;
    }
    ```
4.  **Синтаксис.** Напишіть прототип функції `processUserData`, яка приймає великий об'єкт `string` на ім'я `userData` для читання (без права на зміну) та цілочисельну змінну `errorCounter`, яку вона повинна мати змогу змінювати. Використовуйте найефективніший та найбезпечніший спосіб передачі параметрів.

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

**1. Вказівник vs Посилання:**

  * **Ініціалізація:** Посилання *повинно* бути ініціалізоване в момент створення. Вказівник може бути неініціалізованим або `nullptr`.
  * **Зміна:** Посилання *не можна* перенаправити на іншу змінну після створення. Вказівник можна.
  * **Синтаксис:** Посилання використовується як звичайна змінна (неявне розіменування). Вказівник вимагає явного розіменування (`*`).
  * **Null:** Посилання *не може* бути `null`. Вказівник може.

**2. Pass-by-Reference:**

  * Це спосіб передачі параметрів, при якому функція отримує не копію, а **псевдонім (посилання)** на оригінальну змінну.
  * **Переваги:**
    1.  **Ефективність:** При передачі великих об'єктів (як `string`, вектори, структури) ми **уникаємо дорогої операції копіювання**.
    2.  **Модифікація:** Дозволяє функції **змінювати оригінальну змінну** (що неможливо при передачі за значенням).

**3. Аналіз коду:**

  * **Помилка:** Функція повертає **посилання на локальну змінну (`temp`)**.
  * **Небезпека:** Змінна `temp` існує лише на стеку функції `getSomeValue`. Як тільки функція завершує роботу (після `return`), `temp` **знищується**. Повернене посилання стає "висячим" — воно вказує на невалідну, вже звільнену пам'ять. Спроба прочитати або записати дані через це посилання призведе до **невизначеної поведінки** (Undefined Behavior).

**4. Синтаксис прототипу:**

```cpp
// void processUserData(const string& userData, int& errorCounter);

// Пояснення:
// 1. const string& userData:
//    - string& (за посиланням) - для ефективності, щоб не копіювати великий рядок.
//    - const - для безпеки, гарантуючи, що функція не змінить 'userData'.
// 2. int& errorCounter:
//    - int& (за посиланням) - щоб функція могла змінювати оригінальну змінну 'errorCounter',
//      а не її локальну копію.
void processUserData(const std::string& userData, int& errorCounter);
```

</details>
