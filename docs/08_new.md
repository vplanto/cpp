## Динамічне виділення пам'яті: `new` та `delete`

Досі ми працювали зі **статичним виділенням пам'яті**: компілятор сам визначав, скільки пам'яті потрібно для змінних (у стеку), і автоматично звільняв її при виході з `{}`.

**Динамічне виділення пам'яті** дозволяє програмісту запитувати пам'ять під час виконання програми (в runtime) зі спеціальної області, що називається **"купа" (heap)**. Це дає повний контроль, але й накладає повну відповідальність.

Для цього в C++ використовуються оператори `new` та `delete`, які працюють з вказівниками.

  * **`new`**: Запитує блок пам'яті з "купи" (heap) і повертає вказівник на початок цього блоку.
  * **`delete`**: Повертає блок пам'яті, раніше виділений через `new`, назад у систему.

<!-- end list -->

```cpp
// Статичне виділення (пам'ять у стеку)
int number = 88;
int *p1 = &number; // p1 вказує на пам'ять у стеку

// Динамічне виділення (пам'ять у купі)
int *p2 = new int;    // Виділити пам'ять для одного int в купі
*p2 = 99;             // Записати значення 99 у виділену комірку

cout << "Value: " << *p2 << endl; // Виведе 99

delete p2;            // Звільнити виділену пам'ять. ВАЖЛИВО!
p2 = nullptr;         // Гарна практика: "обнулити" вказівник після звільнення
```

**Ініціалізація при виділенні:**

```cpp
// Ініціалізація фундаментального типу
int *p1 = new int(88);
double *p2 = new double{1.23}; // C++11 синтаксис

// Ініціалізація об'єкта (виклик конструктора)
Date *date1 = new Date(1999, 1, 1);
```

### ❓ Питання до групи

Що станеться, якщо ми викличемо `new int;`, але **забудемо** викликати `delete`? Куди "зникне" ця пам'ять? Як називається ця поширена помилка?

<details markdown="1">
<summary>Натисніть, щоб побачити відповідь</summary>
Це називається **витік пам'яті (memory leak)**. Пам'ять "не зникне". Вона залишиться "зарезервованою" для нашої програми, але оскільки ми втратили вказівник на неї (наприклад, вийшовши з функції), ми вже *ніколи* не зможемо її звільнити. Якщо таких "витоків" багато, програма може "з'їсти" всю доступну пам'ять і "впасти".
</details>

## Динамічні масиви: `new[]` та `delete[]`

Динамічно можна виділяти пам'ять і для масивів, розмір яких може бути визначений під час виконання програми.

  * **`new T[size]`**: Виділяє пам'ять для масиву з `size` елементів типу `T`.
  * **`delete[]`**: **Обов'язково** використовується для звільнення пам'яті, виділеної через `new[]`.

<!-- end list -->

```cpp
int size;
cout << "Enter array size: ";
cin >> size;

// 'size' - це змінна, а не константа.
// Статичний масив 'int arr[size];' не спрацює (це не C++).
// Потрібен динамічний.
int *arr = new int[size]; // Виділення пам'яті для масиву

arr[0] = 10;
arr[1] = 20;
// ...

delete[] arr; // Звільнення пам'яті масиву
arr = nullptr;
```

**Важливо:** Використання `delete` (без `[]`) замість `delete[]` для масиву є серйозною помилкою, що призводить до невизначеної поведінки (зазвичай звільняється лише перший елемент, а решта "тече").

## Масиви та вказівники: Глибокий зв'язок

У C++ ім'я масиву по суті є **вказівником на його перший елемент**.

```cpp
int numbers[] = {10, 20, 30};
// 'numbers' є еквівалентом '&numbers[0]'
```

Це відкриває можливість **вказівникової арифметики**.

### Вказівникова арифметика

Коли ви додаєте `1` до вказівника, його адреса збільшується не на 1 байт, а на **розмір типу даних**, на який він вказує (`sizeof(type)`).

```cpp
int numbers[] = {11, 22, 33};
int *iPtr = numbers; // iPtr вказує на 11 (адреса, напр., 0x1000)

cout << *iPtr << endl; // 11

// Вказівникова арифметика
cout << *(iPtr + 1) << endl; // 22 (еквівалент numbers[1])
cout << *(iPtr + 2) << endl; // 33 (еквівалент numbers[2])

// iPtr + 1 - це адреса 0x1000 + sizeof(int), тобто 0x1004
```

### Передача масивів у функції

Коли масив передається у функцію, насправді передається **лише вказівник** на його перший елемент.

  * Зміни, зроблені всередині функції, **впливають на оригінальний масив**.
  * **Розмір масиву "втрачається"** (функція бачить лише вказівник). Через це розмір масиву *завжди* потрібно передавати окремим параметром (`int size`).
  * У сигнатурі функції `void func(int arr[])` та `void func(int* arr)` є абсолютно еквівалентними.

-----

### Чому `sizeof` не працює для масивів у функціях?

Коли масив передається у функцію, він "розпадається" (decays) до звичайного вказівника. Функція бачить лише адресу першого елемента, а не весь масив.

Оператор `sizeof` демонструє це дуже чітко:

```cpp
#include <iostream>

// Функція отримує 'arr' як вказівник 'int*'
void printArraySize(int arr[], int size) {
    std::cout << "sizeof всередині функції: " << sizeof(arr) << " байт" << std::endl;
    // На 64-бітній системі це виведе 8 (розмір вказівника)
    // На 32-бітній системі це виведе 4 (розмір вказівника)
}

int main() {
    int numbers[10] = {0}; // Масив з 10 int

    // sizeof в main() бачить повний масив
    std::cout << "sizeof в main: " << sizeof(numbers) << " байт" << std::endl;
    // Це виведе 40 (10 елементів * 4 байти)
    
    printArraySize(numbers, 10);
    
    return 0;
}
```

Саме тому ми **завжди** повинні передавати розмір масиву у функцію як окремий параметр (`int size`).

### Робота з діапазоном масиву

Замість того, щоб передавати `(вказівник + розмір)`, ми можемо передати два вказівники: `begin` (на початок діапазону) і `end` (на елемент, *наступний* за кінцем діапазону).

```cpp
// Функція, що працює з діапазоном [begin, end)
int sumRange(const int* pBegin, const int* pEnd) {
    int sum = 0;
    // Ми рухаємо вказівник 'p' вперед,
    // поки він не дорівнюватиме кінцевому вказівнику 'pEnd'
    for (const int* p = pBegin; p != pEnd; ++p) {
        sum += *p; // Додаємо значення, на яке вказує p
    }
    return sum;
}

int main() {
    int arr[] = {10, 20, 30, 40, 50};

    // Сума всього масиву
    // (arr + 5) - це адреса ОДРАЗУ ПІСЛЯ останнього елемента
    int totalSum = sumRange(arr, arr + 5); // 10+20+30+40+50 = 150

    // Сума частини масиву (з індексу 1 до 3, не включаючи 4)
    int partialSum = sumRange(arr + 1, arr + 4); // 20+30+40 = 90
}
```

## Керування доступом: `const` та вказівники

Ключове слово `const` може застосовуватися як до даних, на які вказує вказівник, так і до самого вказівника. Це складна, але важлива тема.

> **Мнемонічне правило:** Читайте оголошення **справа наліво**.

1.  **`const int * ptr`** (або `int const * ptr`)

      * Читаємо: `ptr` — це вказівник (`*`) на `int`, який є `const`.
      * **Що:** **Значення** за вказівником міняти не можна.
      * **Але:** Сам **вказівник** можна перенаправити.
      * *Приклад:* `*ptr = 10; // ПОМИЛКА` | `ptr = &anotherVar; // ДОЗВОЛЕНО`

2.  **`int * const ptr`**

      * Читаємо: `ptr` — це **константний (`const`) вказівник (`*`)** на `int`.
      * **Що:** **Значення** за вказівником міняти можна.
      * **Але:** Сам **вказівник** (адресу, яку він зберігає) міняти не можна.
      * *Приклад:* `*ptr = 10; // ДОЗВОЛЕНО` | `ptr = &anotherVar; // ПОМИЛКА`

3.  **`const int * const ptr`**

      * Читаємо: `ptr` — це **константний (`const`) вказівник (`*`)** на `int`, який є `const`.
      * **Що:** **Ні значення, ні вказівник** міняти не можна.
      * *Приклад:* `*ptr = 10; // ПОМИЛКА` | `ptr = &anotherVar; // ПОМИЛКА`

## Спеціалізовані типи вказівників

  * **Вказівники на функції (Function Pointers):**
    У C++ ім'я функції саме по собі є її адресою в пам'яті. Ми можемо створити вказівник, що зберігатиме цю адресу, і викликати функцію через нього. Це основа для реалізації "колбеків" (callback).

    **Синтаксис:**
    `тип_повернення (* ім'я_вказівника) (список_типів_параметрів);`

    **Приклад:**
    ```cpp
    #include <iostream>
    
    // Звичайна функція
    int add(int a, int b) { return a + b; }
    
    int subtract(int a, int b) { return a - b; }

    int main() {
        // Оголошення вказівника 'pFunc' на функцію,
        // що приймає (int, int) і повертає int
        int (*pFunc)(int, int);

        // 1. Присвоюємо адресу функції 'add'
        pFunc = add; // Можна також писати pFunc = &add;
        std::cout << "Виклик через вказівник: " << pFunc(5, 3) << std::endl; // Виведе 8

        // 2. Тепер перенаправляємо вказівник на іншу функцію
        pFunc = subtract;
        std::cout << "Виклик через вказівник: " << pFunc(5, 3) << std::endl; // Виведе 2

        return 0;
    }
    ```
  * **Узагальнені вказівники (`void*`):** Вказівник типу `void*` може зберігати адресу змінної **будь-якого типу**. Його не можна розіменувати напряму; перед використанням його потрібно явно привести до конкретного типу вказівника (напр., `static_cast<int*>(voidPtr)`).

## Сучасна практика: Розумні вказівники (Smart Pointers)

Ручне управління пам'яттю за допомогою `new` та `delete` є джерелом багатьох помилок (витоки пам'яті, подвійне звільнення). Сучасний C++ (починаючи з C++11) пропонує краще рішення — **розумні вказівники** з заголовка `<memory>`.

Вони автоматично звільняють пам'ять, коли об'єкт більше не потрібен, дотримуючись принципу **RAII (Resource Acquisition Is Initialization)** — "Отримання ресурсу є ініціалізація".

  * **`std::unique_ptr`**: **Унікальне володіння.** Пам'ять автоматично звільняється (викликає `delete`), коли `unique_ptr` виходить з області видимості. Копіювати такий вказівник не можна, лише переміщати.
  * **`std::shared_ptr`**: **Спільне володіння.** Використовує лічильник посилань. Пам'ять звільняється, коли *останній* `shared_ptr`, що вказує на об'єкт, знищується.
  * **`std::weak_ptr`**: "Слабке" посилання на об'єкт, керований `shared_ptr`. Не впливає на лічильник посилань і допомагає розривати циклічні залежності.

### ❓ Питання до групи

Чому `unique_ptr` вважається "безпечнішим" за сирий вказівник `new`? (Підказка: що станеться, якщо ми виділимо пам'ять через `new`, а потім у функції станеться помилка, і ми вийдемо з неї раніше, ніж дійдемо до `delete`?)

<details markdown="1">
<summary>Натисніть, щоб побачити відповідь</summary>
Якщо ми вийдемо з функції раніше (наприклад, через `return` або виключення), наш `delete` ніколи не викличеться, і ми отримаємо **витік пам'яті**. `unique_ptr` — це об'єкт. Навіть якщо ми достроково вийдемо з функції, C++ гарантує, що **деструктор** об'єкта `unique_ptr` буде викликаний. А цей деструктор автоматично викличе `delete` за нас. Це гарантує звільнення пам'яті за будь-яких обставин.
</details>

> **Золоте правило сучасного C++:** Віддавайте перевагу **розумним вказівникам** (`unique_ptr`, `shared_ptr`) над сирими (`new`/`delete`) для управління динамічною пам'яттю.

## Контрольні питання

1.  **Управління пам'яттю.** Що таке "витік пам'яті" (memory leak)? Яка пара операторів у C++ використовується для ручного управління динамічною пам'яттю, і яка помилка в їх використанні призводить до витоків?
2.  **Вказівникова арифметика.** Що виведе наступний код, якщо адреса `arr` дорівнює `0x1000`, а `sizeof(int)` дорівнює 4?
    ```cpp
    int arr[] = {10, 20, 30};
    int* p = arr;
    cout << *(p + 1) << endl;
    cout << (p + 1) << endl;
    ```
3.  **`const` та вказівники.** Поясніть різницю між `const int* ptr` та `int* const ptr`. Наведіть приклади операцій, які будуть дозволені та заборонені для кожного з них.
4.  **Застосування.** Напишіть функцію, яка динамічно створює масив цілих чисел заданого розміру (`size`), заповнює його квадратами чисел від 0 до `size-1` і повертає вказівник на цей масив.

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

**1. Витік пам'яті:**

  * **Витік пам'яті (Memory Leak)** — це ситуація, коли пам'ять, виділена динамічно (у "купі"), більше не використовується програмою, але не була звільнена. Оскільки вказівник на цю пам'ять втрачено, програма не може її повернути системі.
  * **Оператори:** `new` (для виділення) та `delete` (для звільнення). Або `new[]` та `delete[]` для масивів.
  * **Помилка:** Витік стається, коли `new` викликається, а відповідний `delete` — ні (наприклад, його забули написати, або програма вийшла з функції раніше через помилку).

**2. Вказівникова арифметика:**
Код виведе:

```
20
0x1004
```

  * **`*(p + 1)`**: `p` вказує на `arr[0]`. `p + 1` — це адреса `p` + `sizeof(int)`, тобто `0x1000 + 4 = 0x1004`. Це адреса другого елемента (`arr[1]`). Оператор `*` розіменовує цю адресу і дістає значення `20`.
  * **`(p + 1)`**: Це просто обчислення адреси, як описано вище. На екран буде виведено `0x1004` (або еквівалент у 10-вій системі).

**3. `const` та вказівники:**

  * **`const int* ptr` (Вказівник на константу):** "Я вказую на `int`, який є `const`".
      * `*ptr = 5; // ЗАБОРОНЕНО` (не можна змінювати *значення*).
      * `ptr = &otherVar; // ДОЗВОЛЕНО` (можна змінювати *вказівник*).
  * **`int* const ptr` (Константний вказівник):** "Я *константний* вказівник на `int`".
      * `*ptr = 5; // ДОЗВОЛЕНО` (можна змінювати *значення*).
      * `ptr = &otherVar; // ЗАБОРОНЕНО` (не можна змінювати *вказівник*).

**4. Функція створення масиву:**

```cpp
#include <iostream>

// Функція повертає вказівник на int
int* createSquaresArray(int size) {
    // 1. Динамічно виділяємо пам'ять в "купі"
    int* arr = new int[size];

    // 2. Заповнюємо масив
    for (int i = 0; i < size; ++i) {
        arr[i] = i * i;
    }

    // 3. Повертаємо вказівник на початок масиву
    return arr;
}

int main() {
    int n = 5;
    int* myDynamicArray = createSquaresArray(n);

    // Використовуємо масив
    for (int i = 0; i < n; ++i) {
        std::cout << myDynamicArray[i] << " "; // Виведе: 0 1 4 9 16
    }
    std::cout << std::endl;

    // 4. НЕ ЗАБУВАЄМО звільнити пам'ять,
    //    коли вона більше не потрібна!
    delete[] myDynamicArray;
    myDynamicArray = nullptr;

    return 0;
}
```
