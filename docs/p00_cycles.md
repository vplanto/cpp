# Практикум 0: Створюємо "Аналізатор донатів"

## 🎯 Наш "продукт" сьогодні

Забудьте про абстрактні цифри. Наша сьогоднішня мета — написати **реальну консольну утиліту**. Вона називатиметься "Аналізатор донатів".

**Задача:** Програма запитує, скільки донатів ми хочемо проаналізувати (наприклад, `n=5`). Потім вона просить ввести `n` сум донатів. Наприкінці, вона має видати нам повну статистику:

1.  **Загальну суму** всіх донатів.
2.  **Середній донат** (Загальна сума / кількість).
3.  **Найменший** донат.
4.  **Найбільший** донат.

Це класична задача, яка вчить нас працювати з циклами, змінними та приймати рішення — це "серце" програмування.

## 🏁 Експрес-опитування

Перш ніж почнемо, давайте швидко пригадаємо:

1.  Як оголосити змінну для зберігання цілого числа `5`?
2.  Як оголосити змінну для зберігання дробового числа `150.75`?
3.  Якщо ми хочемо повторити дію **точно 10 разів**, яку конструкцію циклу (`for` чи `while`) логічніше обрати?
4.  Що робить оператор `i++`?

<details markdown="1">

1.  `int my_number = 5;`
2.  `double my_donation = 150.75;`
3.  `for` (наприклад, `for (int i = 0; i < 10; ++i)`), оскільки ми заздалегідь знаємо точну кількість ітерацій.
4.  Він збільшує значення змінної `i` на одиницю (це те саме, що `i = i + 1`).

## 🛠️ Крок 1: Розуміння задачі та планування рішення

Це найважливіший етап. Не можна писати код, поки у вас немає плану.

1.  **Вхідні дані:**

      * Нам потрібно запитати кількість донатів. Це ціле число. Беремо **`int n`**.
      * Далі нам потрібно буде зчитувати суми донатів. Вони можуть бути дробовими (з копійками). Нам знадобиться тимчасова змінна **`double currentDonation`**.

2.  **Зберігання даних:**

      * Чи потрібно нам зберігати *всі* донати в масиві?
      * **Ні\!** Для нашої задачі (знайти суму, мін, макс) це не потрібно. Ми можемо обробляти кожен донат "на льоту" — зчитали, оновили статистику, і забули про нього. Це значно економить пам'ять.

3.  **Змінні для результатів (Наша статистика):**

      * `double totalSum = 0.0;` (Для суми, починаємо з 0).
      * `double minDonation;` (Для мінімуму).
      * `double maxDonation;` (Для максимуму).

4.  **Алгоритм (План дій):**

      * Запитати у користувача `int n`.
      * Перевірити, чи `n > 0`. Якщо ні — вийти.
      * **Хитрий момент (ініціалізація min/max):** Ми не можемо просто сказати `minDonation = 0`. А якщо всі донати будуть по 100 грн? Тоді 0 залишиться "найменшим", що є брехнею.
      * **Рішення:** Зчитати **перший** донат *до* основного циклу. Ініціалізувати ним *всі* наші змінні:
          * `cin >> firstDonation;`
          * `totalSum = firstDonation;`
          * `minDonation = firstDonation;`
          * `maxDonation = firstDonation;`
      * Тепер запустити цикл `for`, який виконається `n-1` разів (для решти донатів).
      * **Всередині циклу:**
          * Зчитати наступний `currentDonation`.
          * Додати його до суми: `totalSum += currentDonation;`
          * Перевірити `if (currentDonation < minDonation)` -> оновити `minDonation`.
          * Перевірити `if (currentDonation > maxDonation)` -> оновити `maxDonation`.
      * **Після циклу:**
          * Розрахувати середнє: `double averageDonation = totalSum / n;`
          * Вивести всю статистику: `totalSum`, `averageDonation`, `minDonation`, `maxDonation`.

### ❓ Питання до групи (Давайте поміркуємо)

1.  Наш план — зчитувати перший донат *окремо*. А чи можемо ми інакше? Що, як ми ініціалізуємо `minDonation` **дуже великим** числом (напр., `1000000.0`), а `maxDonation` — **дуже маленьким** (напр., `0.0`)? Чи спрацює такий підхід?
2.  Навіщо ми взагалі обробляємо перший донат окремо? Чи не простіше запустити цикл одразу `n` разів? Як тоді ініціалізувати `min/max`?

## 💻 Крок 2: Написання коду

<details markdown="1">
<summary>Натисніть, щоб побачити рішення</summary>

```cpp
#include <iostream>
#include <iomanip> // Потрібно для форматування виводу (setprecision)

int main() {
    // 1. Оголошуємо змінні
    int n;
    double totalSum = 0.0;
    double minDonation;
    double maxDonation;
    double averageDonation;

    // Встановлюємо гарний вивід для грошей (2 знаки після коми)
    std::cout << std::fixed << std::setprecision(2);

    // 2. Отримуємо кількість донатів
    std::cout << "Введіть кількість донатів для аналізу: ";
    std::cin >> n;

    // 3. Перевірка на валідність
    if (n <= 0) {
        std::cout << "Кількість донатів має бути > 0." << std::endl;
        return 1; // Повертаємо код помилки
    }

    // 4. Ініціалізація (Крок 1 нашого плану)
    std::cout << "Введіть донат 1: ";
    double firstDonation;
    std::cin >> firstDonation;

    // Ініціалізуємо всю статистику першим донатом
    totalSum = firstDonation;
    minDonation = firstDonation;
    maxDonation = firstDonation;

    // 5. Основний цикл (Крок 2 нашого плану)
    // Починаємо з i = 1, бо 0-й донат (перший) ми вже зчитали.
    // Або, якщо рахувати по-людськи, ми зчитали 1-й,
    // тому цикл має пройти ще n-1 разів.
    // `i = 2` бо це "донат 2"
    for (int i = 2; i <= n; ++i) { 
        double currentDonation;
        std::cout << "Введіть донат " << i << ": ";
        std::cin >> currentDonation;

        // Оновлюємо суму
        totalSum += currentDonation; // totalSum = totalSum + currentDonation

        // Перевіряємо та оновлюємо мінімум
        if (currentDonation < minDonation) {
            minDonation = currentDonation;
        }

        // Перевіряємо та оновлюємо максимум
        if (currentDonation > maxDonation) {
            maxDonation = currentDonation;
        }
    }

    // 6. Розрахунок середнього
    averageDonation = totalSum / n;

    // 7. Вивід результатів
    std::cout << "\n--- Статистика по збору ---" << std::endl;
    std::cout << "Загальна сума:     " << totalSum << " грн." << std::endl;
    std::cout << "Середній донат:  " << averageDonation << " грн." << std::endl;
    std::cout << "Найменший донат: " << minDonation << " грн." << std::endl;
    std::cout << "Найбільший донат: " << maxDonation << " грн." << std::endl;

    return 0; // Успішне завершення
}
```

## 🤯 Бонус-задача: Чому "Факторіал" ламає ваш комп'ютер

У вашому файлі була задача "Факторіал `n!`". Давайте швидко подивимось, чому вона така підступна. `n!` — це `1 * 2 * 3 * ... * n`.

**Проблема:** Факторіал росте *неймовірно* швидко.

  * `10!` = 3,628,800 (поміщається в `int`)
  * `15!` = 1,307,674,368,000 (вже **не поміщається** в `int` або `long long`\!)
  * `20!` = 2,432,902,008,176,640,000 (ледве поміщається в `unsigned long long`)

**Код:**

```cpp
// ...
int n;
// ОБОВ'ЯЗКОВО unsigned long long, щоб уникнути переповнення
unsigned long long factorial = 1;

std::cin >> n;

for (int i = 1; i <= n; ++i) {
    factorial *= i;
}
std::cout << factorial << std::endl;
```

### ❓ Питання до групи

Що станеться, якщо ми використаємо `int` або `long long` для розрахунку `20!`? Програма видасть помилку? Чи вона "зламається"? (Правильна відповідь: вона *мовчки* видасть неправильний результат через **переповнення типу**). Це одна з найнебезпечніших помилок у C++.

## 🧠 Контрольні питання

1.  **Ефективність.** У нашій задачі "Аналізатор донатів", чому ми не стали зберігати всі введені донати в масиві? В якому випадку використання масиву було б *необхідним*?
2.  **Типи даних.** Що станеться, якби ми використали тип `long long` замість `unsigned long long` для зберігання факторіалу числа 20?
3.  **Алгоритми.** Як би ви змінили код нашої утиліти "Аналізатор донатів", щоб він працював не для `n` донатів, а просто зчитував донати, *поки користувач не введе 0*? (Підказка: який цикл тут підійде краще — `for` чи `while`?)

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

**1. Ефективність (Масиви)**

  * **Чому не використали:** Для наших цілей (сума, мін, макс) масив був не потрібен. Ми можемо обробити кожне число і забути про нього. Це економить пам'ять (О(1) пам'яті замість O(N)).
  * **Коли масив необхідний:** Масив був би *абсолютно необхідним*, якби задача вимагала, наприклад, **"вивести всі донати, які вищі за середній"** або **"відсортувати донати"**. Тобто, у будь-якій задачі, де нам потрібно *повторно* звернутися до даних після їх зчитування.

**2. Типи даних (Факторіал)**

  * `20!` (приблизно 2.43 \* 10^18) **більше**, ніж максимальне значення для `signed long long` (приблизно 9.22 \* 10^18 / 2 = \~4.6 \* 10^18, якщо рахувати позитивні та негативні. *Оновлення*: `long long` на більшості систем це 64 біти, макс. значення \~9.22 \* 10^18. `unsigned long long` \~1.8 \* 10^19. Отже, `20!` *не поміститься* навіть у `long long`. *[Викладач: уточніть розміри типів для вашої системи, але суть у тому, що `unsigned` дає вдвічі більший діапазон для додатних чисел]*. Якщо ми використаємо `long long`, станеться **переповнення типу**, і програма мовчки видасть **неправильний, "зациклений" результат** (ймовірно, від'ємне число), а не помилку компіляції.

**3. Зміна алгоритму (Цикли)**

  * Це ідеальна задача для циклу **`while`** (або `do-while`).
  * **Логіка:**
    1.  Замість `for (int i = 0; i < n; ++i)` ми б написали `while (true)` (безкінечний цикл).
    2.  Всередині циклу зчитуємо `currentDonation`.
    3.  Додаємо перевірку: `if (currentDonation == 0) { break; }` — `break` негайно розірве наш безкінечний цикл.
    4.  Якщо ж `currentDonation` не 0, ми обробляємо його (додаємо до суми, перевіряємо мін/макс).
    5.  Також нам знадобиться окремий лічильник `int donationCount = 0;`, який ми б збільшували (`donationCount++`) всередині циклу, щоб потім розрахувати середнє.

</details>
