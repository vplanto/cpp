# Лекція 11: Робота з файлами (`<fstream>`)

## 🏁 Експрес-опитування

У минулій лекції ми навчилися "пакувати" дані у `struct`. Давайте пригадаємо:

1.  Яку проблему вирішують `struct` у порівнянні з "паралельними масивами"?
2.  Якщо у нас є об'єкт `Player p1;`, як звернутися до його поля `health`?
3.  Якщо у нас є *вказівник* `Player* pPtr = &p1;`, як звернутися до поля `health`?
4.  Що робить `enum` і навіщо він потрібен?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  `struct` дозволяє об'єднати **різні** типи даних ( `string`, `int`, `double`) в одну логічну "коробку", замість того, щоб тримати їх у окремих, не пов'язаних масивах.
2.  Через **оператор-крапку (`.`)**: `p1.health = 100;`.
3.  Через **оператор-стрілку (`->`)**: `pPtr->health = 100;`.
4.  `enum` створює набір іменованих цілочисельних констант (наприклад, `IDLE`, `ATTACKING`). Це робить код набагато чистішим і безпечнішим, ніж використання "магічних чисел" (0, 1).

</details>

## 1\. Проблема: Дані зникають

Досі всі наші програми мали одну велику проблему: як тільки програма закривається, всі дані (рахунок, введена інформація) **зникають**. Вони жили у **RAM (Оперативній пам'яті)**, яка є енергозалежною.

Щоб зберегти дані назавжди, нам потрібно записати їх у **файл** (тобто, на жорсткий диск або SSD).

### Потоки (Streams): Єдина абстракція

C++ використовує потужну абстракцію під назвою **потік (stream)** для виконання всіх операцій вводу та виводу.

Потік — це сутність, з якої програма може "витягувати" (`>>`) або в яку може "вставляти" (`<<`) символи послідовно, один за одним .

Найважливіше те, що програмі не потрібно знати деталі про пристрій (чи це консоль, чи клавіатура, чи файл). Робота з усіма ними однакова.

#### Стандартні потоки (Standard Streams)

Коли ваша програма запускається, вона вже має три попередньо підключені потоки для зв'язку з терміналом (консоллю) .
 
1.  **Standard Input (`stdin`)** 
    * **Призначення:** Ввід даних (за замовчуванням — клавіатура).
    * **Об'єкт C++:** `std::cin`.

2.  **Standard Output (`stdout`)** 
    * **Призначення:** Звичайний вивід даних (за замовчуванням — дисплей).
    * **Об'єкт C++:** `std::cout`.

3.  **Standard Error (`stderr`)** 
    * **Призначення:** Вивід повідомлень про помилки (за замовчуванням — дисплей).
    * **Об'єкт C++:** `std::cerr` (небуферизований) та `std::clog` (буферизований).

Коли ми підключаємо `<fstream>`, ми просто створюємо **нові** потоки (`ofstream`, `ifstream`), які підключені не до консолі, а до **файлів** на вашому диску. Але синтаксис роботи з ними (`<<` та `>>`) залишається тим самим.

## 2\. Робота з файлами: `#include <fstream>`

Бібліотека `<fstream>` (file stream) надає нам три нові класи :

  * `ofstream` (output file stream): Для **запису** у файл. (Працює як `cout`).
  * `ifstream` (input file stream): Для **читання** з файлу. (Працює як `cin`).
  * `fstream` (file stream): Для читання **та** запису.

Чому існують окремі `ifstream` та `ofstream`, якщо `fstream` вміє все? **Безпека та ясність намірів**. Якщо ви бачите `ifstream`, ви точно знаєте, що ця частина коду *тільки читає* файл і не може його пошкодити.

## 3\. "Продукт" 1: Запис у файл (`ofstream`)

**Задача:** Написати програму, яка питає ім'я гравця та його рекорд, і зберігає цей рекорд у файл `highscore.txt`.

**Алгоритм (Завжди 4 кроки):**

1.  Підключити `<fstream>`.
2.  Створити об'єкт `ofstream`.
3.  **Відкрити** файл за допомогою `.open()`.
4.  **Записати** дані у файл, використовуючи оператор `<<`.
5.  **Закрити** файл за допомогою `.close()`.

<!-- end list -->

```cpp
#include <iostream>
#include <fstream> // 1. Підключаємо бібліотеку
#include <string>

int main() {
    std::string nickname;
    int score;

    std::cout << "Введіть ваш нік: ";
    std::cin >> nickname;
    std::cout << "Введіть ваш рекорд: ";
    std::cin >> score;

    // 2. Створюємо об'єкт вихідного потоку
    std::ofstream outFile;

    // 3. Відкриваємо файл (асоціюємо потік з файлом) 
    // Якщо файлу не існує, він буде створений.
    // Якщо файл існує, він буде ПЕРЕЗАПИСАНИЙ (стертий).
    outFile.open("highscore.txt");

    // 4. Записуємо у файл - так само, як у cout!
    outFile << "Nickname: " << nickname << std::endl;
    outFile << "Score: " << score << std::endl;

    // 5. Закриваємо файл
    // Це ОБОВ'ЯЗКОВО. Це "змиває" буфер  
    // і звільняє ресурс для ОС.
    outFile.close();

    std::cout << "Рекорд збережено!" << std::endl;
    return 0;
}
```

## 4\. "Продукт" 2: Читання з файлу (`ifstream`)

**Задача:** Написати програму, яка зчитує дані з `highscore.txt` і виводить їх у консоль.

**Алгоритм (Схожий):**

1.  Підключити `<fstream>`.
2.  Створити об'єкт `ifstream`.
3.  **Відкрити** файл.
4.  **Перевірити**, чи файл відкрився (А що, як його не існує?).
5.  **Зчитати** дані з файлу, використовуючи `>>` або `getline`.
6.  **Закрити** файл.

<!-- end list -->

```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    // 2. Створюємо об'єкт вхідного потоку
    std::ifstream inFile;

    // 3. Відкриваємо файл для читання
    inFile.open("highscore.txt");

    // 4. ПЕРЕВІРКА!
    // if (!inFile.is_open()) або простіше:
    if (!inFile) {
        std::cerr << "Помилка: Не вдалося відкрити файл highscore.txt" << std::endl;
        return 1; // Повертаємо код помилки
    }

    // 5. Зчитуємо дані
    std::string label1, label2, nickname;
    int score;

    // Зчитуємо по одному "слову"
    inFile >> label1 >> nickname; // Зчитає "Nickname:" і "Ghost"
    inFile >> label2 >> score;    // Зчитає "Score:" і "9900"

    // 6. Закриваємо файл
    inFile.close();

    // Виводимо в консоль
    std::cout << "Завантажено останній рекорд:" << std::endl;
    std::cout << nickname << " - " << score << std::endl;

    return 0;
}
```

### ❓ Питання до групи

У нас є `cout` для виводу в консоль, і `cerr` для виводу помилок. Чому ми використали `std::cerr` для помилки, а не `std::cout`? 

<details markdown="1">
<summary>Натисніть, щоб побачити відповідь</summary>
`cout` (standard output) використовує **буферизацію**. Якщо ваша програма "впаде", `cout` може не встигнути "змити" (flush) буфер, і ви ніколи не побачите повідомлення про помилку.

`cerr` (standard error) **небуферизований** (або буферизується по-іншому). Він гарантує, що повідомлення про помилку з'явиться на екрані *негайно*, що критично важливо для діагностики проблем.

</details>

## 5\. Режими відкриття файлів (`ios::app`)

**Проблема:** Коли ми запускаємо "Продукт 1", він **стирає** старий рекорд (`ios::trunc` - це режим за замовчуванням для `ofstream`). Як нам *додати* новий рекорд у кінець файлу, не видаляючи старі?

**Рішення:** Використати режим **`ios::app` (append)**.

```cpp
// Потрібно вказати другий параметр в .open()
// ios::app означає "append" (додати в кінець) 
outFile.open("highscore.txt", std::ios::app);

// Якщо ви використовуєте кілька режимів, поєднуйте їх через | (бітове АБО)
// outFile.open("data.bin", std::ios::out | std::ios::binary); 
```

| Режим | Опис |
| :--- | :--- |
| `ios::in` | (За замовчуванням для `ifstream`) Відкрити для читання. |
| `ios::out`| (За замовчуванням для `ofstream`) Відкрити для запису. |
| `ios::trunc` | (За замовчуванням для `ofstream`) **Стерти** вміст файлу, якщо він існує. |
| `ios::app` | (Append) **Додати** дані в кінець файлу. Нічого не стирає. |
| `ios::binary` | Відкрити у двійковому режимі (для `int` або об'єктів, а не тексту). |

## 6\. Читання до кінця файлу

**Проблема:** `cin >>` зчитує по одному слову. `getline` зчитує по одному рядку. Як нам зчитати *весь* файл, якщо ми не знаємо, скільки там слів чи рядків?

**Рішення:** Найкращий спосіб — використовувати сам потік як умову в циклі `while`.

**"Продукт 3": Лічильник слів у файлі** 

```cpp
#include <iostream>
#include <fstream>
#include <string>

int main() {
    std::ifstream file("some_text.txt");
    if (!file) {
        std::cerr << "Не можу відкрити файл!" << std::endl;
        return 1;
    }

    std::string word;
    int wordCount = 0;

    // МАГІЯ:
    // Вираз (file >> word) робить дві речі:
    // 1. Намагається зчитати слово у 'word'.
    // 2. Повертає 'true', якщо зчитування вдалося, і 'false',
    //    якщо досягнуто кінця файлу (або сталася помилка).
    while (file >> word) {
        // Якщо ми тут, зчитування вдалося
        wordCount++;
    }

    file.close();
    std::cout << "Файл містить " << wordCount << " слів." << std::endl;
    return 0;
}
```

**Аналогічно для `getline`:**

```cpp
// ...
std::string line;
int lineCount = 0;
while (std::getline(file, line)) {
    lineCount++;
}
std::cout << "Файл містить " << lineCount << " рядків." << std::endl;
// ...
```

## 7\. Бонус: `stringstream` (Парсинг рядків)

**Проблема:** Ми зчитали з файлу цілий рядок `std::string line = "score: 1204"`. Як нам дістати з нього *лише* число `1204`?

**Рішення:** Використати `#include <sstream>` (string stream).
`stringstream` — це потік, який "живе" не у файлі чи консолі, а **всередині `std::string`**. Він дозволяє вам "витягувати" (`>>`) дані з рядка так само, як ви це робите з `cin`.

```cpp
#include <iostream>
#include <string>
#include <sstream> // Підключаємо stringstream

int main() {
    std::string line = "score: 1204 user: Ghost";
    
    std::string tempLabel; // Для сміття ("score:", "user:")
    int scoreValue;
    std::string userValue;

    // 1. Створюємо stringstream і "заряджаємо" його нашим рядком
    std::stringstream ss(line); 

    // 2. "Витягуємо" дані, як з cin
    ss >> tempLabel >> scoreValue; // tempLabel="score:", scoreValue=1204
    ss >> tempLabel >> userValue;  // tempLabel="user:", userValue="Ghost"
    
    std::cout << "Рахунок: " << scoreValue << std::endl; // 1204
    std::cout << "Гравець: " << userValue << std::endl; // Ghost

    return 0;
}
```

## 8\. Контрольні питання

1.  **Концепція.** У чому різниця між `ofstream` та `ifstream`?
2.  **Режими.** Ви хочете зберегти лог-файл. Щоразу, коли програма запускається, вона має *додавати* нові рядки в кінець файлу, а не стирати старі. Який режим (`ios::`) ви маєте використати в `file.open()`?
3.  **`endl` vs `\n`.** У лекції 1 ми говорили, що `endl` "змиває буфер" (flushes). Чому при записі у файл **1000** разів на секунду використання `endl` в циклі буде жахливою ідеєю, а `\n` — ні?
4.  **Читання файлу.** У чому полягає елегантність циклу `while (file >> word)`? Що він перевіряє?
5.  **Парсинг.** У вас є `std::string data = "x: 10.5 y: -3.0";`. Який інструмент (`<fstream>`, `<sstream>` чи `<iostream>`) ви використаєте, щоб "витягнути" з цього рядка два числа `double`?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  **`ofstream` (output file stream)** використовується *тільки для запису* у файл. **`ifstream` (input file stream)** використовується *тільки для читання* з файлу.
2.  Потрібно використати **`std::ios::app`** (append).
3.  **Проблема `endl`:** `endl` не лише додає `\n`, але й *примусово синхронізує* буфер (`flush`). Це означає, що **1000 разів на секунду** ваша програма буде зупинятися і "штовхати" дані на фізичний диск. Це надзвичайно повільна операція. `\n` просто додає символ у буфер, дозволяючи ОС самій вирішити, коли ефективно записати дані на диск (наприклад, коли буфер заповниться).
4.  **Елегантність `while(file >> word)`:** Цей вираз одночасно **намагається зчитати** дані і **повертає `true` (якщо вдалося) або `false` (якщо досягнуто кінця файлу або сталася помилка)**. Це дозволяє в один рядок реалізувати безпечний цикл читання до кінця файлу.
5.  Потрібно використати **`<sstream>`**. Ви створюєте `std::stringstream ss(data);`, а потім "витягуєте" з нього дані: `ss >> tempChar >> x_val >> tempChar >> y_val;` .

</details>
