<summary>Натисніть, щоб побачити відповіді</summary>

1.  **Ні, не може.** Функція отримує лише **копію** змінної.
2.  Ми передали її "за посиланням". Синтаксис: `void func(int& x)`. Тепер `x` — це не копія, а **псевдонім** оригіналу.

## Вступ

Сьогодні ми розберемо один з найпотужніших, але й найскладніших інструментів C++ — **вказівники (pointers)** як низькорівневий спосіб прямої роботи з пам'яттю. Правильне їх використання є ключем до написання швидкого та ефективного коду, особливо в ігровій розробці.

Ми будемо вчитися на практичному прикладі: напишемо програму для аналізу списку рекордів у грі, щоб зрозуміти, навіщо нам потрібен доступ не просто до значень, а до їх **розташування в пам'яті**.

## Частина 1: Проблема — нам потрібна не тільки відповідь, а й місце

Уявімо, що у нас є масив, який зберігає рекорди гравців за 5 раундів гри.

```cpp
int gameScores[5] = {8500, 9200, 7800, 9800, 9100};
```

**Задача:** Написати функцію, яка знаходить найкращий результат.

Давайте напишемо просту версію, яка повертає лише значення.

```cpp
int findMaxScore(int scores[], int size) {
    int maxScore = scores[0];
    for (int i = 1; i < size; ++i) {
        if (scores[i] > maxScore) {
            maxScore = scores[i];
        }
    }
    return maxScore;
}
```

**Питання:** "Ми викликали цю функцію і отримали відповідь `9800`. Все чудово. Але що ми втратили? Ми знаємо, *який* рекорд найкращий, але не знаємо, *де* він знаходиться (в якому раунді). Як нам, наприклад, нарахувати бонус за цей рекорд, змінивши його в оригінальному масиві?"

**Проблема:** Функція, що повертає лише значення, не дає нам доступу до **оригінальної комірки пам'яті**. Нам потрібен інструмент, який може вказувати на **місце**, а не на значення.

## Частина 2: Вказівники — "закладки" в пам'яті

**Вказівник (`*`)** — це змінна, яка зберігає не звичайне значення (як `9800`), а **адресу в пам'яті** іншої змінної.

Уявіть пам'ять як довгу вулицю з будинками.

  * **Звичайна змінна (`int x = 10;`)** — це **вміст** будинку.
  * **Вказівник (`int* p;`)** — це **записка з адресою** цього будинку.

### Два головні оператори

1.  **Оператор отримання адреси (`&`)** — "Дай мені адресу цієї змінної".
    ```cpp
    int score = 100;
    int* pScore = &score; // pScore тепер зберігає адресу змінної score
    ```
2.  **Оператор розіменування (`*`)** — "Покажи, що лежить за адресою, записаною в цьому вказівнику".
    ```cpp
    std::cout << *pScore; // Виведе 100 - значення, що лежить за адресою
    *pScore = 150;        // Змінюємо значення за адресою. Тепер score = 150
    ```

### ❓ Питання до групи (Перевірка розуміння)

Давайте виконаємо код:

```cpp
int score = 100;
int* pScore = &score;
```

Тепер дайте відповідь:

1.  Що таке `score`? (Значення чи адреса?)
2.  Що таке `&score`? (Значення чи адреса?)
3.  Що таке `pScore`? (Значення чи адреса?)
4.  Що таке `*pScore`? (Значення чи адреса?)

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  `score` — це **значення** (`100`).
2.  `&score` — це **адреса** (напр., `0x7ffc...`).
3.  `pScore` — це теж **адреса** (вона зберігає `&score`, тобто `0x7ffc...`).
4.  `*pScore` — це **значення** (воно "йде" за адресою `0x7ffc...` і дістає `100`).

</details>

## Частина 3: Вирішуємо нашу задачу за допомогою вказівників

Давайте перепишемо нашу функцію так, щоб вона повертала **вказівник** на комірку з максимальним значенням.

```cpp
#include <iostream>

// Чому ми передаємо два параметри:
// 1. scores[] — адреса початку масиву в пам'яті.
// 2. size — кількість елементів. Оскільки ми передаємо лише адресу,
//    сама адреса не містить жодної інформації про довжину масиву!
int* findBestScorePtr(int scores[], int size) {
    // Перевірка, чи масив не порожній
    if (size <= 0) {
        return nullptr; // Повертаємо нульовий вказівник, якщо даних немає
    }

    // Створюємо вказівник, який буде "закладкою" на найкращий результат
    int* pBestScore = &scores[0]; // Починаємо з припущення, що перший елемент - найкращий

    // Шукаємо кращий результат
    for (int i = 1; i < size; ++i) {
        // Порівнюємо ЗНАЧЕННЯ поточного елемента...
        if (scores[i] > *pBestScore) { // ...зі ЗНАЧЕННЯМ, на яке вказує наша "закладка"
            // Якщо знайшли кращий, переставляємо "закладку" на нову адресу
            pBestScore = &scores[i];
        }
    }

    return pBestScore;
}
```

Тепер подивимося, як це використовувати:

```cpp
int main() {
    int gameScores[5] = {8500, 9200, 7800, 9800, 9100};

    // Отримуємо не значення, а вказівник на найкращий результат.
    // Передаючи gameScores, ми передаємо адресу початку масиву.
    // Ця адреса передається як значення — тобто функція отримує копію адреси!
    int* pChampionScore = findBestScorePtr(gameScores, 5);

    if (pChampionScore != nullptr) { // ЗАВЖДИ перевіряємо вказівник
        std::cout << "Найкращий результат: " << *pChampionScore << std::endl;

        // Тепер ми можемо змінити оригінальний масив через вказівник!
        std::cout << "Нараховуємо бонус +100..." << std::endl;
        *pChampionScore += 100;
    }

    // Виведемо весь масив, щоб побачити зміни
    std::cout << "Оновлені результати раундів:" << std::endl;
    for (int i = 0; i < 5; ++i) {
        std::cout << gameScores[i] << " "; // Виведе: 8500 9200 7800 9900 9100
    }
    std::cout << std::endl;

    return 0;
}
```

Ми не тільки знайшли найкращий результат, але й змогли його змінити, знаючи його **розташування**.

> [!NOTE]
> ### Важливий нюанс: як масив передається у функцію і чому потрібен `size`?
> Раніше ми вже з'ясували, що ім'я масиву `gameScores` позначає **адресу його початку** в пам'яті (адресу нульового елемента).
> 
> Зверніть увагу на два принципові моменти:
> 
> 1. **Передача адреси як значення (копія адреси):**
>    * Ми **не копіюємо** весь масив із 5 елементів (це було б вкрай повільно для великих даних).
>    * У функцію передається **адреса як звичайне значення (pass-by-value)** — тобто функція отримує **копію адреси** початку масиву.
>    * Оскільки ця скопійована адреса вказує на комірки оригінального масиву `gameScores` у пам'яті, усі операції всередині функції (наприклад, `scores[i]` чи `&scores[i]`) працюють безпосередньо з оригінальними даними.
> 
> 2. **Чому `size` відомий у `main`, але невідомий у `findBestScorePtr`?**
>    * У функції `main` масив оголошено безпосередньо (`int gameScores[5]`), тому компілятору і коду в `main` його розмір достеменно відомий.
>    * Але коли ми передаємо масив у функцію, передається **лише числова адреса** першого елемента.
>    * **Адреса не містить жодних метаданих** про те, скільки елементів іде після неї і де масив закінчується. Функція бачить тільки те, *де* масив починається.
>    * Саме тому в C/C++ разом з адресою масиву **обов'язково окремим параметром передають його розмір (`int size`)**. Без цього параметр-лічильник цикла не знав би, коли зупинитися, і програма вийшла б за межі масиву в чужу пам'ять.

## Частина 4: Практикум з читання коду (Code Tracing)

Уміння подумки «трасувати» пам'ять комп'ютера — критична навичка для роботи з вказівниками. Давайте разом подивимось показові приклади. Спробуйте спочатку самостійно визначити, що виведе кожен фрагмент, а потім розберімо, що саме відбувається в пам'яті.

### Приклад 1: Переприв'язка вказівника vs зміна значення (Aliasing)

Уважно простежте, куди вказує кожен вказівник у кожен момент часу:

```cpp
#include <iostream>

int main() {
    int hpWarrior = 100;
    int hpMage = 60;

    int* pCurrentTarget = &hpWarrior;
    int* pSavedTarget = pCurrentTarget;

    *pCurrentTarget -= 40;       // Крок 1
    pCurrentTarget = &hpMage;    // Крок 2
    *pCurrentTarget -= 15;       // Крок 3
    *pSavedTarget -= 10;         // Крок 4

    std::cout << "Воїн: " << hpWarrior << ", Маг: " << hpMage << std::endl;
    std::cout << "*pCurrentTarget: " << *pCurrentTarget << ", *pSavedTarget: " << *pSavedTarget << std::endl;

    return 0;
}
```

<details markdown="1">
<summary>Розбір і відповідь</summary>

**Що буде виведено:**
```text
Воїн: 50, Маг: 45
*pCurrentTarget: 45, *pSavedTarget: 50
```

**Покрокове трасування пам'яті:**
1. `pCurrentTarget = &hpWarrior;` — вказівник дивиться на комірку `hpWarrior` (100).
2. `pSavedTarget = pCurrentTarget;` — скопійовано **адресу**. Тепер обидва вказівники дивляться на одну й ту саму змінну `hpWarrior` (явище псевдонімів — *aliasing*).
3. **Крок 1 (`*pCurrentTarget -= 40`):** розіменовуємо адресу, значення `hpWarrior` зменшується зі 100 до **60**.
4. **Крок 2 (`pCurrentTarget = &hpMage`):** ми змінюємо **саму адресу** всередині `pCurrentTarget`. Тепер він вказує на `hpMage`. Але `pSavedTarget` продовжує вказувати на `hpWarrior`!
5. **Крок 3 (`*pCurrentTarget -= 15`):** розіменовуємо нову адресу — `hpMage` зменшується з 60 до **45**.
6. **Крок 4 (`*pSavedTarget -= 10`):** розіменовуємо стару збережену адресу — `hpWarrior` зменшується з 60 до **50**.

</details>

### Приклад 2: Пастка передачі вказівника у функцію

Часто новачки вважають, що вказівник у функції можна перенаправити на іншу змінну. Подивіться на цей код:

```cpp
#include <iostream>

void heal(int* pTargetHp) {
    if (pTargetHp != nullptr) {
        *pTargetHp += 25; // Зміна значення за адресою
    }
}

void switchTarget(int* pCurrent, int* pNewTarget) {
    pCurrent = pNewTarget; // Спроба перемкнути вказівник
}

int main() {
    int bossHp = 500;
    int minionHp = 80;

    int* pActive = &bossHp;

    heal(pActive);
    switchTarget(pActive, &minionHp);
    heal(pActive);

    std::cout << "bossHp: " << bossHp << ", minionHp: " << minionHp << std::endl;
    std::cout << "*pActive: " << *pActive << std::endl;

    return 0;
}
```

<details markdown="1">
<summary>Розбір і відповідь</summary>

**Що буде виведено:**
```text
bossHp: 550, minionHp: 80
*pActive: 550
```

**Чому ціль не перемкнулася на `minionHp`?**
* **Фундаментальне правило, яке треба раз і назавжди запам'ятати:**  
  У системному програмуванні **все завжди передається за значенням**:
  1. Ми передаємо або саме **значення** (копію даних);
  2. Або передаємо **адресу** як значення (копію адреси).
* Немає жодної можливості повернути напряму інше значення або підмінити оригінальну змінну викликача через формальні параметри! Параметр функції — це завжди ізольована локальна копія.
* Коли ми викликали `switchTarget(pActive, &minionHp)`, параметр `pCurrent` отримав **копію адреси** з `pActive`.
* Рядок `pCurrent = pNewTarget;` змінив лише цю **локальну копію адреси** всередині функції. Після виходу з функції ця змінна знищилася!
* Оригінальний вказівник `pActive` у функції `main` не змінився: він як дивився на `bossHp`, так і продовжує дивитися.
* Єдине, що ми можемо змінити зсередини функції через вказівник — це **вміст комірки ЗА адресою** через розіменування (`*pTargetHp += 25`). Але сам фактичний вказівник викликача переприв'язати зсередини функції неможливо.
* Тому другий виклик `heal(pActive)` знову полікував боса (525 + 25 = 550), а міньйон так і залишився з 80 HP.

</details>

### Приклад 3: Пошук вільного слота в інвентарі

У класичних іграх (наприклад, Diablo чи Minecraft) інвентар зберігається у вигляді масиву слотів, де значення `0` означає «порожній слот»:

```cpp
#include <iostream>

int main() {
    const int SLOTS_COUNT = 5;
    int backpack[SLOTS_COUNT] = {15, 42, 0, 8, 0}; // 0 = порожньо

    int* pFirstFreeSlot = nullptr;

    // Шукаємо перший порожній слот
    for (int i = 0; i < SLOTS_COUNT; ++i) {
        if (backpack[i] == 0) {
            pFirstFreeSlot = &backpack[i];
            break; // Знайшли перший — зупиняємось!
        }
    }

    // Кладемо новий знайдений артефакт (код 99)
    if (pFirstFreeSlot != nullptr) {
        *pFirstFreeSlot = 99;
    }

    std::cout << "Оновлений рюкзак: ";
    for (int i = 0; i < SLOTS_COUNT; ++i) {
        std::cout << backpack[i] << " ";
    }
    std::cout << std::endl;

    return 0;
}
```

<details markdown="1">
<summary>Розбір і відповідь</summary>

**Що буде виведено:**
```text
Оновлений рюкзак: 15 42 99 8 0
```

**Чому цей патерн такий важливий?**
1. Вказівник `pFirstFreeSlot` ініціалізовано `nullptr`. Якщо рюкзак буде забитий під зав'язку (жодного `0`), вказівник так і залишиться `nullptr`.
2. Завдяки перевірці `if (pFirstFreeSlot != nullptr)` програма не впаде і не перезапише чужу пам'ять, якщо вільних місць немає.
3. Ми знайшли комірку за адресою і модифікували її напряму на місці (`in-place`), без створення проміжних копій масиву.

</details>

## Частина 5: Пишемо разом — Реальний кейс: «Дрон-медик тактичного загону»

А тепер напишемо повноцінний алгоритм, максимально наближений до реальних задач системної та ігрової розробки (Game AI / Embedded Systems).

### Постановка задачі

У тактичній стратегії підрозділ автономного дрона-медика стежить за показниками здоров'я бійців загону.
Здоров'я бійців зберігається в масиві `int squadHp[]`.

Дрон має обмежений запас медикаментів і повинен втручатися **тільки у критичній ситуації**:
1. Функція повинна знайти бійця, у якого **найменше здоров'я серед тих, чий показник опустився нижче критичного порогу** `criticalThreshold` (наприклад, менше 30 HP).
2. Функція має повернути **вказівник (`int*`)** на комірку здоров'я цього бійця безпосередньо в оригінальному масиві, щоб дрон міг ввести стимулятор.
3. Якщо критично поранених бійців немає (у всіх `HP >= criticalThreshold`), функція повинна повернути **`nullptr`** (дрону нема кого рятувати, медикаменти слід зберегти).
4. У `main` ми перевіряємо результат: якщо ціль знайдено — додаємо `+40 HP` (але не більше максимальних `100 HP`) і виводимо оновлений стан загону.

<details markdown="1">
<summary>Підказка та прототип функції</summary>

* **Повертає:** `int*` (адресу пораненого бійця або `nullptr`, якщо лікувати нікого не потрібно).
* **Приймає:** 
  * `int hpList[]` — адресу початку масиву показників HP;
  * `int size` — кількість бійців (обов'язково, бо адреса сама по собі не знає розміру!);
  * `int criticalThreshold` — числовий поріг критичного стану.

```cpp
int* findCriticallyInjured(int hpList[], int size, int criticalThreshold);
```

</details>

### Крок 2: Реалізація алгоритму пошуку

Починаємо з припущення, що критично поранених немає (`pTarget = nullptr`). Коли бачимо бійця з HP нижче порогу:
* якщо це перший такий боєць (`pTarget == nullptr`) — зберігаємо його адресу;
* якщо ми вже когось знаходили раніше — перевіряємо, чи новий знайдений боєць має **ще менше** HP, ніж поточний кандидат (`hpList[i] < *pTarget`).

```cpp
int* findCriticallyInjured(int hpList[], int size, int criticalThreshold) {
    if (size <= 0) {
        return nullptr;
    }

    int* pTarget = nullptr; // Поки що жодного критично пораненого не знайдено

    for (int i = 0; i < size; ++i) {
        // Перевіряємо, чи боєць у зоні небезпеки
        if (hpList[i] < criticalThreshold) {
            // Якщо це перший кандидат АБО його стан гірший за раніше знайденого
            if (pTarget == nullptr || hpList[i] < *pTarget) {
                pTarget = &hpList[i]; // Запам'ятовуємо адресу найбільш постраждалого
            }
        }
    }

    return pTarget; // Поверне адресу або nullptr
}
```

### Крок 3: Повна робоча програма з викликом у `main`

Скомпонуємо все разом та перевіримо роботу на реальних даних:

```cpp
#include <iostream>

int* findCriticallyInjured(int hpList[], int size, int criticalThreshold) {
    if (size <= 0) return nullptr;

    int* pTarget = nullptr;

    for (int i = 0; i < size; ++i) {
        if (hpList[i] < criticalThreshold) {
            if (pTarget == nullptr || hpList[i] < *pTarget) {
                pTarget = &hpList[i];
            }
        }
    }
    return pTarget;
}

int main() {
    const int SQUAD_SIZE = 5;
    // Початкові показники здоров'я 5 бійців:
    // Боєць 0: 85 HP
    // Боєць 1: 42 HP
    // Боєць 2: 18 HP (критично!)
    // Боєць 3: 90 HP
    // Боєць 4: 25 HP (критично!)
    int squad[SQUAD_SIZE] = {85, 42, 18, 90, 24};
    int threshold = 30; // Межа критичного стану

    std::cout << "Стан загону до прибуття дрона:" << std::endl;
    for (int i = 0; i < SQUAD_SIZE; ++i) {
        std::cout << "Боєць [" << i << "]: " << squad[i] << " HP" << std::endl;
    }

    // 1. Дрон сканує загін
    int* pPatient = findCriticallyInjured(squad, SQUAD_SIZE, threshold);

    // 2. Обов'язкова перевірка на nullptr
    if (pPatient != nullptr) {
        std::cout << "\n[!] Дрон виявив критичного бійця з " << *pPatient << " HP!" << std::endl;

        // 3. Пряме лікування через розіменування адреси оригіналу
        *pPatient += 40;
        if (*pPatient > 100) {
            *pPatient = 100; // Обмеження максимуму
        }

        std::cout << "[+] Введено стимулятор. Новий рівень здоров'я: " << *pPatient << " HP" << std::endl;
    } else {
        std::cout << "\n[i] Усі бійці у стабільному стані. Ресурси дрона збережено." << std::endl;
    }

    std::cout << "\nСтан загону після роботи дрона:" << std::endl;
    for (int i = 0; i < SQUAD_SIZE; ++i) {
        std::cout << "Боєць [" << i << "]: " << squad[i] << " HP" << std::endl;
    }

    return 0;
}
```

**Результат виконання програми:**
```text
Стан загону до прибуття дрона:
Боєць [0]: 85 HP
Боєць [1]: 42 HP
Боєць [2]: 18 HP
Боєць [3]: 90 HP
Боєць [4]: 25 HP

[!] Дрон виявив критичного бійця з 18 HP!
[+] Введено стимулятор. Новий рівень здоров'я: 58 HP

Стан загону після роботи дрона:
Боєць [0]: 85 HP
Боєць [1]: 42 HP
Боєць [2]: 58 HP
Боєць [3]: 90 HP
Боєць [4]: 25 HP
```

Зверніть увагу: серед двох поранених (`18` та `25`) дрон безпомилково обрав найважчого бійця (`18`), напряму оновив комірку в масиві `squad`, а решта бійців залишилися без змін.

> [!TIP]
> ### ❓ Питання на роздуми: що буде, якщо у двох бійців однаковий мінімальний рівень HP?
> Уявімо, що і в бійця [2], і в бійця [4] **однаково критичний стан — по 18 HP**. Кого з них полікує дрон?
> 
> Погляньте на умову оновлення кандидата в нашому алгоритмі:
> ```cpp
> if (pTarget == nullptr || hpList[i] < *pTarget)
> ```
> * Оскільки в умові стоїть **суворе менше (`<`)**, для другого бійця умова `18 < 18` дасть `false`. Вказівник `pTarget` **не перезапишеться**, і дрон обере **першого** зустрінутого бійця (з меншим індексом).
> * Якби ми поставили **несуворе менше (`<=`)**, вказівник переставився б на нову адресу, і дрон полікував би **останнього** бійця з таким рівнем здоров'я.
> 
> У багатьох практичних завданнях ця різниця (`<` чи `<=`) може бути **дуже принциповою** (визначення пріоритетності черги, стабільність алгоритму тощо) — завжди звертайте на це увагу!

## Контрольні питання

1.  **Концепція.** Поясніть своїми словами, що зберігає змінна-вказівник? Чим це відрізняється від звичайної змінної `int`?
2.  **Синтаксис.** Який оператор використовується, щоб отримати **адресу** змінної? А який — щоб отримати **значення**, що лежить за адресою, збереженою у вказівнику?
3.  **Аналіз коду.** Що буде виведено на екран в результаті виконання наступного коду?
    ```cpp
    int a = 50;
    int* pA = &a;
    *pA = 100;
    std::cout << a << std::endl;
    ```
4.  **Вибір.** Вам потрібно написати функцію, яка може "провалитися" і не знайти потрібний елемент у масиві. Що краще повернути в цьому випадку: `0`, `-1` чи `nullptr`? Чому?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

**1. Концепція:**

  * Звичайна змінна `int a = 50;` зберігає **безпосереднє значення** (число 50).
  * Змінна-вказівник `int* pA = &a;` зберігає **адресу в пам'яті** (наприклад, `0x7ffc...`), де лежить змінна `a`.

**2. Синтаксис:**

  * Щоб отримати **адресу**, використовується оператор "амперсанд": **`&`** (напр., `&a`).
  * Щоб отримати **значення** за адресою, використовується оператор "розіменування" або "зірочка": **`*`** (напр., `*pA`).

**3. Аналіз коду:**

  * На екран буде виведено **100**.
  * **Пояснення:** `pA` зберігає адресу `a`. Рядок `*pA = 100;` означає: "піди за адресою, що зберігається в `pA` (тобто до комірки `a`), і запиши туди `100`". Таким чином, значення `a` змінюється з 50 на 100.

**4. Вибір (Обробка помилок):**

  * **Найкраща відповідь: `nullptr`**.
  * **Чому:** `0` або `-1` можуть бути *валідними значеннями* в масиві. Якщо наша функція `findMaxScore` поверне `-1`, ми не зможемо зрозуміти: це вона не знайшла елемент, чи вона знайшла елемент, який *дійсно дорівнює* -1?
  * `nullptr` — це спеціальне значення, яке означає "цей вказівник не вказує ні на що". Це чіткий, однозначний сигнал про помилку, який неможливо сплутати з реальним значенням. Саме тому у нашому практикумі ми перевіряли `if (pChampionScore != nullptr)`.

</details>
