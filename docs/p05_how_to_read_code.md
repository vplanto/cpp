## 🏁 Експрес-опитування

Цей практикум об'єднує **все**, що ми вивчили. Давайте пригадаємо:

1.  Якщо ми хочемо, щоб функція **змінила** нашу змінну (але ця змінна **не може** бути `nullptr`), що ми використаємо у параметрі: вказівник (`*`) чи посилання (`&`)?
2.  Якщо параметр **опціональний** (може бути `nullptr`), що ми використаємо?
3.  Якщо ми хочемо передати "важкий" об'єкт, але **заборонити** функції його змінювати, як ми оголосимо параметр?
4.  Що таке "глобальна" змінна і чому її використання вважається поганою практикою?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  **Посилання (`&`)**. Воно гарантує, що змінна існує, і дозволяє її змінювати з чистим синтаксисом.
2.  **Вказівник (`*`)**. Тільки він може мати значення `nullptr`, що чітко показує "відсутність" параметра.
3.  **Константне посилання (`const &`)**. `&` — щоб уникнути копіювання, `const` — щоб гарантувати безпеку.
4.  **Глобальна змінна** — це змінна, оголошена поза будь-якою функцією. Це погано, тому що будь-яка функція може її несподівано змінити, що робить код непередбачуваним і складним для відладки.

</details>

## 🔬 "Пацієнт" на столі: Код гри "Хрестики-Нулики"

Ось повний, робочий код гри. Він написаний не ідеально, але він працює і є чудовим прикладом для аналізу.

```cpp
/*
 * Консольна гра "Хрестики-Нулики" для двох гравців.
 * Демонстрація базової структури C++ програми.
 */

#include <iostream>

// --- 1. Глобальні константи та змінні ---
// (Погана практика, але часто зустрічається у новачків)
const int BOARD_SIZE = 3;
char board[BOARD_SIZE][BOARD_SIZE]; // Наша ігрова дошка
char currentPlayer = 'X';           // Поточний гравець ('X' або 'O')

// --- 2. Прототипи функцій ---
// (Повідомляємо компілятору, які функції існують)
void initializeBoard();
void drawBoard();
bool placeMove(int move);
bool checkWin();
bool checkDraw();
void switchPlayer();

// --- 3. Точка входу: Головна функція ---
int main() {
    initializeBoard(); // Готуємо дошку
    bool gameRunning = true;

    // Це -- Головний Ігровий Цикл (Game Loop)
    while (gameRunning) {
        // Крок 1: Малюємо поточний стан
        drawBoard();

        // Крок 2: Отримуємо хід гравця
        int move;
        std::cout << "Гравець " << currentPlayer << ", введіть ваш хід (1-9): ";
        std::cin >> move;

        // Крок 3: Обробляємо хід
        if (!placeMove(move)) {
            std::cout << "Невірний хід! Ця клітинка вже зайнята або не існує." << std::endl;
            continue; // Пропускаємо решту циклу і починаємо знову
        }

        // Крок 4: Перевіряємо умови завершення гри
        if (checkWin()) {
            drawBoard(); // Малюємо фінальну дошку
            std::cout << "Гравець " << currentPlayer << " переміг!" << std::endl;
            gameRunning = false;
        } else if (checkDraw()) {
            drawBoard();
            std::cout << "Нічия!" << std::endl;
            gameRunning = false;
        } else {
            // Крок 5: Якщо ніхто не виграв, передаємо хід
            switchPlayer();
        }
    }

    return 0;
}

// --- 4. Визначення функцій (Реалізація) ---

/**
 * @brief Ініціалізує дошку, заповнюючи її цифрами 1-9.
 */
void initializeBoard() {
    char k = '1';
    for (int i = 0; i < BOARD_SIZE; ++i) { // Цикл по рядках
        for (int j = 0; j < BOARD_SIZE; ++j) { // Цикл по стовпцях
            board[i][j] = k;
            k++;
        }
    }
}

/**
 * @brief Малює дошку в консолі.
 */
void drawBoard() {
    std::cout << "-------" << std::endl;
    for (int i = 0; i < BOARD_SIZE; ++i) {
        std::cout << "|";
        for (int j = 0; j < BOARD_SIZE; ++j) {
            std::cout << board[i][j] << "|";
        }
        std::cout << std::endl;
        std::cout << "-------" << std::endl;
    }
}

/**
 * @brief Перемикає поточного гравця з 'X' на 'O' і навпаки.
 */
void switchPlayer() {
    if (currentPlayer == 'X') {
        currentPlayer = 'O';
    } else {
        currentPlayer = 'X';
    }
}

/**
 * @brief Намагається поставити хід (currentPlayer) у комірку 'move'.
 * @param move Номер комірки (1-9).
 * @return true, якщо хід успішний, false - якщо ні.
 */
bool placeMove(int move) {
    // Вхід (1-9) треба перетворити на індекси (0-2, 0-2)
    int row = (move - 1) / BOARD_SIZE;
    int col = (move - 1) % BOARD_SIZE;

    // Перевірка коректності ходу
    if (move < 1 || move > 9 || board[row][col] == 'X' || board[row][col] == 'O') {
        return false;
    }

    // Хід коректний, ставимо
    board[row][col] = currentPlayer;
    return true;
}

/**
 * @brief Перевіряє, чи поточний гравець виграв.
 * @return true, якщо є 3 в ряд.
 */
bool checkWin() {
    // Перевірка рядків та стовпців
    for (int i = 0; i < BOARD_SIZE; ++i) {
        if (board[i][0] == currentPlayer && board[i][1] == currentPlayer && board[i][2] == currentPlayer)
            return true; // Перемога в рядку
        if (board[0][i] == currentPlayer && board[1][i] == currentPlayer && board[2][i] == currentPlayer)
            return true; // Перемога в стовпці
    }

    // Перевірка діагоналей
    if (board[0][0] == currentPlayer && board[1][1] == currentPlayer && board[2][2] == currentPlayer)
        return true; // Головна діагональ
    if (board[0][2] == currentPlayer && board[1][1] == currentPlayer && board[2][0] == currentPlayer)
        return true; // Побічна діагональ

    return false;
}

/**
 * @brief Перевіряє, чи на дошці нічия (немає вільних ходів).
 * @return true, якщо ходів не залишилось.
 */
bool checkDraw() {
    // Якщо хоч одна клітинка НЕ є 'X' або 'O', гра триває
    for (int i = 0; i < BOARD_SIZE; ++i) {
        for (int j = 0; j < BOARD_SIZE; ++j) {
            if (board[i][j] != 'X' && board[i][j] != 'O') {
                return false; // Знайшли вільну клітинку, нічиєї немає
            }
        }
    }
    // Цикл завершився, вільних клітинок не знайдено
    return true;
}
```

## Частина 1: Як читати цей код? (Стратегія)

Коли ви бачите новий файл, очі "розбігаються". Куди дивитися?

**Стратегія:** Ніколи не читайте код зверху вниз, як книгу. Читайте його, як карту скарбів, починаючи з **точки входу**.

1.  **Знайдіть `int main()`.** Це *завжди* початок. Весь код у секціях 1, 2, 4 — це лише "інструменти", які чекають, поки `main()` їх викличе.
2.  **Прочитайте `main()` покроково.**
      * `initializeBoard();` — Окей, щось готує дошку.
      * `while (gameRunning)` — Ага, **ігровий цикл**. Це серце програми.
      * `drawBoard();` — Малює.
      * `std::cin >> move;` — Читає хід.
      * `placeMove(move);` — Перевіряє і ставить хід.
      * `if (checkWin()) ... else if (checkDraw()) ... else switchPlayer();` — Класична логіка: перевірка перемоги, перевірка нічиєї, передача ходу.
3.  **Занурюйтесь у функції за потребою.** Тепер, коли ви зрозуміли *потік* у `main()`, ви можете досліджувати, *як* працюють "чорні скриньки".
      * "А як працює `placeMove`?" -> Тепер йдемо і читаємо *лише* тіло функції `placeMove`.
      * "А як він перевіряє перемогу?" -> Читаємо `checkWin`.

Це "Top-Down" (зверху-вниз) підхід: від загальної картини (`main`) до деталей (функції).

## Частина 2: Як це побудовано? (Структура)

Весь цей файл можна розділити на 4 логічні секції (я їх позначив у коді):

1.  **Секція 1: Глобальні дані (`board`, `currentPlayer`)**

      * **Що це:** Це *стан* (state) нашої гри. Це дані, які потрібні *всім* функціям.
      * **Проблема:** Автор використав **глобальні змінні**. Це просто, але небезпечно. Будь-яка функція може їх змінити. `drawBoard` несподівано може змінити `currentPlayer`.
      * **Як було б краще?** Створити `struct GameState` і передавати посилання на нього (`GameState& state`) у кожну функцію. (Ми це вивчимо пізніше).

2.  **Секція 2: Прототипи функцій**

      * **Що це:** "Зміст" для компілятора. C++ читає файл зверху вниз. Якби `main()` викликав `drawBoard()`, не побачивши її оголошення, була б помилка. Цей блок вирішує проблему "курки та яйця".

3.  **Секція 3: Точка входу (`main`)**

      * **Що це:** "Мозок" програми. Вона не реалізує логіку сама, а **оркеструє** виклики інших, більш дрібних функцій. Це гарна практика. `main()` має бути короткою і читабельною.

4.  **Секція 4: Визначення функцій**

      * **Що це:** "Робітники". Кожна функція виконує **одну чітку задачу** (Single Responsibility Principle).
      * `drawBoard` тільки малює.
      * `checkWin` тільки перевіряє.
      * `placeMove` тільки ставить хід.
      * Це *чудова* практика, яка робить код легким для розуміння та відладки.

## Частина 3: Як це іменовано? (Naming Conventions)

Аналіз імен дає зрозуміти "стиль" автора.

  * **Константи:** `BOARD_SIZE`

      * **Конвенція:** `UPPER_SNAKE_CASE` (всі літери великі, розділені `_`).
      * **Навіщо:** Це стандартна конвенція C++ для констант та макросів. Коли ви бачите таке ім'я, ви одразу знаєте — це значення, яке не можна змінювати.

  * **Змінні:** `board`, `currentPlayer`, `gameRunning`, `move`

      * **Конвенція:** `camelCase` (перше слово з малої літери, наступні з великої) або прості імена.
      * **Навіщо:** Стандартна конвенція для змінних у багатьох мовах (Java, C\#, C++).

  * **Функції:** `initializeBoard`, `drawBoard`, `checkWin`, `switchPlayer`

      * **Конвенція:** `camelCase`.
      * **Навіщо:** Імена функцій — це **дієслова**. Вони описують *дію*.
      * **`bool checkWin()`** — "перевірити перемогу". Ім'я функції, що повертає `bool`, часто починається з `is...` (`isRunning`) або `check...` (`checkWin`). Це дуже добре.

## Контрольні питання

1.  **Читання коду:** З якої функції ви завжди маєте починати аналіз C++ програми?
2.  **Структура (Дані):** Як у цьому коді зберігається ігрове поле? Який тип даних використовується?
3.  **Структура (Логіка):** Чому автор виніс `checkWin()` та `drawBoard()` в окремі функції, а не написав весь код усередині циклу `while` в `main()`?
4.  **Неймінг:** Яка конвенція іменування використана для константи `BOARD_SIZE`?
5.  **Відладка (Пошук помилок):** Уявіть, що користувач вводить не `5`, а `hello`. Що станеться з `std::cin >> move;`? (Підказка: `cin` "зламається", і цикл, ймовірно, стане нескінченним). Як би ви це виправили?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

**1. Читання коду:**
Завжди з **`int main()`**. Це точка входу та "карта" всієї програми.

**2. Структура (Дані):**
Ігрове поле зберігається у **глобальній** змінній `board`. Це **двовимірний масив** (масив масивів) типу `char` розміром 3х3: `char board[BOARD_SIZE][BOARD_SIZE];`.

**3. Структура (Логіка):**
Це називається **принципом єдиної відповідальності (Single Responsibility Principle)** та **декомпозицією**.

  * **Читабельність:** `main()` стає коротким і зрозумілим (читається як речення: "малюй, візьми хід, перевір...").
  * **Відладка:** Якщо дошка малюється неправильно, ви знаєте, що помилка *тільки* у функції `drawBoard()`.
  * **Повторне використання:** Ми викликаємо `drawBoard()` у двох місцях (на початку циклу і в кінці гри). Завдяки функції нам не треба було копіювати код.

**4. Неймінг:**
`UPPER_SNAKE_CASE` (всі літери великі, слова розділені підкресленням). Це стандарт для констант у C++.

**5. Відладка (Помилка `cin`):**

  * Коли `std::cin >> move;` очікує `int`, але отримує `hello`, потік `cin` входить у стан помилки (`fail state`).
  * Він **припиняє** зчитувати дані. `move` залишається неініціалізованим (або 0).
  * Виклик `placeMove(move)` поверне `false`.
  * Цикл `while` повториться. `drawBoard()`... і `std::cin >> move;` *миттєво* знову "провалиться", тому що потік вже у стані помилки.
  * Результат: **нескінченний цикл**, що постійно друкує "Невірний хід\!".
  * **Як виправити:** Потрібно додавати перевірку стану `cin` та очищувати буфер:
    ```cpp
    while (!(std::cin >> move)) { // Якщо зчитування провалилось
        std::cout << "Будь ласка, введіть число (1-9): ";
        std::cin.clear(); // Скидаємо прапор помилки
        // "З'їдаємо" всі неправильні символи з буфера до кінця рядка
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    }
    ```
