# Практикум 8: Файлові потоки (`fstream`) — Створюємо "Save Game"

## 🎯 Наш "продукт" сьогодні

Наша програма "Менеджер Паті" з минулого разу має фатальну ваду: щойно ми її закриваємо, вся наша група (`Player* party`) зникає. Дані, що живуть в RAM (стек/купа), — тимчасові.

**Задача:** Написати три утиліти для роботи з файлом `party.sav`:

1.  **"Save Game" (Запис):** Взяти наш динамічний масив `Player` і зберегти його у файл (`ofstream`).
2.  **"Load Game" (Читання):** Зчитати дані з `party.sav` і відновити стан гри (`ifstream`).
3.  **"File Inspector" (Маніпуляція):** Утиліта, яка **не читаючи весь файл**, може миттєво сказати, скільки в ньому байт (розмір). Це і є **маніпуляція потоком** (`seekg`, `tellg`).

## Частина 1: Зберігаємо гру (`ofstream`)

Спочатку напишемо "утиліту 1". Вона візьме дані і запише їх у файл.

**Ключові інструменти:**

  * `#include <fstream>`
  * `std::ofstream` (output file stream)
  * `file.open("ім'я файлу")`
  * `file.close()`

<details markdown="1">
<summary>Натисніть, щоб побачити код "Save Game"</summary>

```cpp
#include <iostream>
#include <fstream> // Обов'язково для роботи з файлами
#include <string>

struct Player {
    std::string name;
    std::string className;
    int level;
};

int main() {
    // Наші дані, які ми хочемо зберегти
    Player party[2];
    party[0] = {"Ghost", "Recon", 10};
    party[1] = {"Soap", "Assault", 9};

    // 1. Створюємо об'єкт потоку виводу
    std::ofstream saveFile;

    // 2. Відкриваємо файл. 
    // За замовчуванням, файл відкривається в режимі ios::out | ios::trunc
    // ios::trunc ОЗНАЧАЄ: "Якщо файл існує, СТЕРТИ ВЕСЬ ЙОГО ВМІСТ"
    saveFile.open("party.sav");

    // 3. Перевіряємо, чи файл вдалося відкрити
    if (!saveFile.is_open()) {
        std::cerr << "ПОМИЛКА: Неможливо відкрити файл для запису!" << std::endl;
        return 1;
    }

    std::cout << "Збереження гри..." << std::endl;

    // 4. Записуємо дані у файл - синтаксис, як у `cout`!
    // Ми будемо використовувати простий CSV-подібний формат: name,class,level
    for (int i = 0; i < 2; ++i) {
        saveFile << party[i].name << "," 
                 << party[i].className << "," 
                 << party[i].level << "\n"; // '\n' для нового рядка
    }

    // 5. Закриваємо файл
    // Це ОБОВ'ЯЗКОВО. Ця команда "змиває" буфер
    // і повідомляє ОС, що ми завершили роботу з файлом.
    saveFile.close();

    std::cout << "Збереження завершено." << std::endl;
    return 0;
}
```

</details>

## Частина 2: Додаємо гравця (`ios::app`)

**Проблема:** Якщо ми запустимо код вище вдруге, він **перезапише** наш файл. Як нам *додати* нового гравця в кінець файлу?

**Рішення:** Використати режим **`ios::app` (append)**.

```cpp
// Відкриваємо файл у режимі "додавання в кінець"
saveFile.open("party.sav", std::ios::app); 
```

### ❓ Питання до групи (Буферизація)

У файлі `WriteStreamExt.cpp` є дивний `sleep(60)`. Уявіть, що ви запустили код, який пише у файл 1000 рядків, а потім "зависає" на `sleep(60)`. Якщо ви відкриєте файл у Блокноті *під час* `sleep`, що ви там побачите?

<details markdown="1">
<summary>Міркуємо разом (Логіка з `WriteStreamExt.cpp`)</summary>

**Відповідь:** Ви не побачите **нічого**. Файл буде порожнім.

**Чому?** Запис на диск — це *повільно*. C++ не записує кожен символ одразу. Він збирає дані у тимчасовій пам'яті — **буфері** (`streambuf`). Дані потраплять на диск (процес називається `flush` або "синхронізація"), лише коли:

1.  Буфер заповниться.
2.  Ви *явно* викличете `file.flush()`.
3.  Ви використаєте `std::endl` (який автоматично викликає `flush`).
4.  Ви викличете `file.close()` (який теж викликає `flush`).

Код у `WriteStreamExt.cpp` "зависає" *до* виклику `close()`, тому дані "сидять" у буфері в RAM. Це показує, чому важливо завжди коректно закривати файли. 

</details>

## Частина 3: Завантажуємо гру (`ifstream` та `stringstream`)

Тепер напишемо "утиліту 2" — зчитувач. Вона використає логіку з `ReadStream.cpp` та `WordCounter.cpp`.

**Ключові інструменти:**

  * `std::ifstream` (input file stream)
  * `while (std::getline(file, line))` — найкращий спосіб читати файл по рядках.
  * `std::stringstream` — для "парсингу" рядка, який ми зчитали.

<details markdown="1">
<summary>Натисніть, щоб побачити код "Load Game"</summary>

```cpp
#include <iostream>
#include <fstream>
#include <string>
#include <sstream> // Потрібен для парсингу рядка

struct Player {
    std::string name;
    std::string className;
    int level;
};

int main() {
    // 1. Створюємо об'єкт вхідного потоку
    std::ifstream loadFile("party.sav");

    // 2. Перевіряємо, чи файл існує і чи ми можемо його читати
    if (!loadFile.is_open()) {
        std::cerr << "ПОМИЛКА: Файл збереження 'party.sav' не знайдено!" << std::endl;
        return 1;
    }

    std::cout << "Завантаження гри..." << std::endl;
    std::string line;

    // 3. Найкращий спосіб читати файл по рядках:
    // (Логіка з ReadStream.cpp)
    // getline() зчитує рядок і повертає 'true',
    // поки не дійде до кінця файлу (EOF).
    while (std::getline(loadFile, line)) {
        
        // 4. "Парсимо" зчитаний рядок (напр., "Ghost,Recon,10")
        std::stringstream ss(line);
        std::string tempField; // Тимчасова змінна для полів
        Player p;

        // Витягуємо дані, розділені комою
        std::getline(ss, p.name, ',');
        std::getline(ss, p.className, ',');
        
        std::getline(ss, tempField, ','); // Зчитуємо рівень (який є текстом)
        p.level = std::stoi(tempField); // stoi = "string to integer"

        // Виводимо завантажені дані
        std::cout << "  > Завантажено: " << p.name 
                  << " (Клас: " << p.className 
                  << ", Рівень: " << p.level << ")" << std::endl;
    }

    // 5. Закриваємо файл
    loadFile.close();
    return 0;
}
```

</details>

### ❓ Питання до групи (Пастка `eof()`)

У файлі `ReadStreamExt.cpp` використовується цикл `while (!file.eof())`. Це дуже поширена помилка новачків. Чому цей код гірший, ніж наш `while (getline(..))`?

<details markdown="1">
<summary>Міркуємо разом...</summary>
Прапор `eof()` (End of File) стає `true` **тільки після** того, як ми спробуємо зчитати щось *за* кінцем файлу.

При `while (!file.eof())`:

1.  Ми зчитуємо останній рядок. `eof()` все ще `false`.
2.  Цикл починається знову.
3.  `getline()` намагається зчитати, нічого не знаходить (встановлює `eof()`), **але `line` не змінюється**.
4.  Цикл **виводить останній рядок ДВІЧІ**.

Цикл `while (getline(file, line))` — ідеальний. Він читає *і* перевіряє успішність в одній операції.

</details>

## Частина 4: Маніпуляція потоком (`seekg`, `tellg`)

Це **обов'язкова** частина. Наша "Утиліта 3" ("File Inspector") повинна отримувати розмір файлу, не читаючи його.

**Ключові інструменти:**

  * **Курсори:** Уявіть, що у файлі є два курсори: `get` (де ми читаємо) і `put` (де ми пишемо).
  * `seekg()` (seek get): **Переміщує** курсор читання.
  * `tellg()` (tell get): **Повідомляє**, де зараз курсор читання.
  * **Режими:** `ios::beg` (початок), `ios::cur` (поточна позиція), `ios::end` (кінець).

<details markdown="1">
<summary>Натисніть, щоб побачити код "File Inspector" (з `FileSize.cpp`)</summary>

```cpp
#include <iostream>
#include <fstream>

int main() {
    // 1. Відкриваємо файл у бінарному режимі,
    //    щоб коректно рахувати байти
    std::ifstream file("party.sav", std::ios::binary);
    if (!file) {
        std::cerr << "Не вдалося відкрити файл." << std::endl;
        return 1;
    }

    // 2. Отримуємо початкову позицію (зазвичай 0)
    std::streampos begin = file.tellg();

    // 3. Переміщуємо 'get' курсор на 0 байт
    //    відносно кінця файлу (ios::end)
    file.seekg(0, std::ios::end);

    // 4. Отримуємо кінцеву позицію
    std::streampos end = file.tellg();

    file.close();

    // 5. Розмір файлу - це різниця між кінцем і початком
    std::cout << "Розмір файлу: " << (end - begin) << " байт." << std::endl;
    
    return 0;
}
```

</details>

## Частина 5: Професійна обробка помилок (Прапори стану)

Що станеться, якщо файл пошкоджено, або диск заповнився під час запису? Наш потік "зламається".

**Ключові інструменти** (з `FileFlags.cpp`):

  * `file.good()`: `true`, якщо все ОК.
  * `file.fail()`: `true`, якщо сталася логічна помилка (напр., ми намагалися зчитати "abc" в `int`).
  * `file.bad()`: `true`, якщо сталася серйозна, незворотна помилка (напр., диск відключився).
  * `file.eof()`: `true`, якщо досягнуто кінця файлу.
  * `file.clear()`: Скидає прапори помилок (напр., `fail`), щоб ми могли продовжити роботу.

4.  **Прапори.** Під час зчитування `file >> number;` користувач ввів "text". Який прапор стану (`bad`, `fail` чи `eof`) буде встановлено?
5.  **Буферизація.** Ваша програма 10 хвилин писала дані у файл, але раптово "впала" (crashed), не виконавши `file.close()`. Ви відкриваєте файл і бачите, що він порожній. Чому так сталося, і які **дві** команди могли б запобігти цьому (якби їх викликали *до* падіння)?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  Потрібно використати `std::ios::app` (append): `saveFile.open("scores.txt", std::ios::app);`.
2.  Тому що `!file.eof()` стає `false` *тільки після* невдалої спроби читання. Це призводить до того, що **останній рядок файлу обробляється двічі**. `while (getline(..))` читає *і* перевіряє успіх в одній операції, що є коректним.
3.  `file.seekg(10, std::ios::beg);` та `file.seekg(-5, std::ios::cur);` .
4.  Буде встановлено прапор `file.fail()`, оскільки це помилка *форматування* (текст не можна перетворити на число), а не повна відмова диска.
5.  **Чому:** Дані знаходились у **буфері** в RAM і не були "змиті" (flushed) на диск . **Як запобігти:**
    1.  Періодично викликати `file.flush();` 
    2.  Використовувати `std::endl` (який автоматично викликає `flush`) замість `\n` (але це повільніше).

</details>
