# Лекція 10: `struct` та `enum` — Створюємо власні типи даних

## 🏁 Експрес-опитування

У минулих лекціях та практикумах ми навчилися керувати пам'яттю. Давайте пригадаємо:

1.  У практикумі `p01` ("MVP матчу") ми мали 3 нікнейми та 3 масиви з кілами. Які два *окремі* масиви ми використовували для їх зберігання?
2.  Якщо ми хочемо написати функцію, яка *не копіює* великий `std::string`, але й *не може його змінювати*, як ми оголосимо її параметр?
3.  Якщо ми хочемо, щоб функція могла повернути вказівник на "ніщо" (наприклад, пошук не дав результату), яке ключове слово ми повернемо?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

1.  Ми використовували `char nicknames[3][50]` та `int kills[3]`. Це називається **паралельними масивами**.
2.  Як **константне посилання**: `const std::string& str`.
3.  Ми повернемо **`nullptr`**.

## 1\. Проблема "паралельних масивів"

Уявіть, що нам потрібно зберігати дані про 100 гравців. У кожного гравця є нікнейм, здоров'я, мана, сила, спритність та інтелект.

Згідно з нашими поточними знаннями, нам доведеться створити **шість** паралельних масивів:

```cpp
const int PLAYER_COUNT = 100;

std::string nicknames[PLAYER_COUNT];
int health[PLAYER_COUNT];
int mana[PLAYER_COUNT];
int strength[PLAYER_COUNT];
int dexterity[PLAYER_COUNT];
int intelligence[PLAYER_COUNT];
```

Щоб отримати дані 5-го гравця, нам доведеться лізти у `nicknames[4]`, `health[4]`, `mana[4]`... Це незручно, неефективно і легко призводить до помилок.

**Рішення:** Нам потрібен спосіб "запакувати" всі ці різні типи даних в один *власний* тип.

-----

## 2\. Структури (`struct`)

**Структура (`struct`)** — це користувацький тип даних, який дозволяє об'єднувати (або "пакувати") змінні різних типів в єдине ціле. Ці змінні всередині структури називаються **членами (members)**.

Це проміжний крок до Об'єктно-Орієнтованого Програмування (ООП).

### Синтаксис

Ми визначаємо "креслення" для нашого нового типу за допомогою ключового слова `struct`.

```cpp
// 1. Оголошення "креслення"
// Це ще не дані, це лише опис того, як вони виглядають.
struct Player {
    std::string nickname;
    int health;
    int mana;
    int strength;
    int dexterity;
    int intelligence;
}; // <-- Не забудьте крапку з комою в кінці! 
```

Тепер, замість 6-ти масивів, ми можемо створити **один** масив нашого нового типу `Player`:

```cpp
Player allPlayers[PLAYER_COUNT];
```

### Доступ до членів: Оператор "крапка" (`.`)

Щоб отримати доступ до полів (членів) всередині структури, використовується **оператор "крапка" (`.`)**.

```cpp
// 2. Створення екземпляра (instance) структури
Player p1; // Створюємо одну змінну типу Player

// 3. Доступ та присвоєння значень
p1.nickname = "Ghost";
p1.health = 100;
p1.mana = 50;
p1.strength = 10;

// Можна ініціалізувати одразу (порядок важливий!)
Player p2 = {"Soap", 100, 50, 8, 12, 10};

// Доступ до масиву структур
allPlayers[0].nickname = "Price";
allPlayers[0].health = 100;
```

### ❓ Питання до групи

У чому, на вашу думку, головна відмінність між `struct Player` та `int scores[5]`? (Підказка: які типи даних вони можуть зберігати?)

<details markdown="1">
<summary>Натисніть, щоб побачити відповідь</summary>

  * **Масив (`int[]`)** може зберігати *багато* значень, але **одного типу** (тільки `int`).
  * **Структура (`struct`)** може зберігати *багато* значень **різних типів** ( `string`, `int`, `double` тощо) в одній "коробці".

</details>

## 3\. `struct` та Функції

Оскільки `struct` — це тип, ми можемо передавати його у функції. І тут ми знову стикаємося з вибором: за значенням чи за посиланням?

```cpp
// 1. Погано: Передача за значенням (Pass-by-Value)
// Створюється ПОВНА КОПІЯ 'p'. Якщо 'Player' буде містити
// багато даних (інвентар, історію), це буде ДУЖЕ повільно.
void printPlayer(Player p) {
    cout << p.nickname << endl;
}

// 2. Добре: Передача за константним посиланням (Pass-by-const-Reference)
// Копія НЕ створюється. 'p' - це псевдонім оригіналу.
// 'const' гарантує, що ми не змінимо гравця випадково.
void printPlayer(const Player& p) {
    cout << p.nickname << endl;
    // p.health = 50; // ПОМИЛКА КОМПІЛЯЦІЇ (бо p - константне)
}

// 3. Добре: Передача за посиланням (Pass-by-Reference)
// Копія НЕ створюється. Використовується для функцій,
// які ПОВИННІ змінювати гравця (напр., 'levelUp').
void levelUp(Player& p) {
    p.strength += 2;
    p.health = 100; // Повне здоров'я
}

int main() {
    Player p1 = {"Ghost", 80, 50, 10, 10, 10};
    
    printPlayer(p1);  // Виклик (2)
    levelUp(p1);      // Виклик (3)
    printPlayer(p1);  // 'strength' тепер 12, 'health' 100
}
```

## 4\. `struct` та Вказівники: Оператор "стрілка" (`->`)

Ми також можемо мати **вказівник** на структуру. Це особливо важливо при роботі з **динамічною пам'яттю** (`new`).

```cpp
// Створюємо гравця не в стеку, а в "купі" (heap)
Player* pPlayer = new Player();

// Як отримати доступ до членів?
// Ми маємо спочатку розіменувати вказівник (*), а потім взяти член (.)
(*pPlayer).nickname = "Ghost"; // Працює, але незручно і некрасиво

// Синтаксичний цукор: Оператор "стрілка" (->)
// Робить те саме: розіменовує вказівник і бере член
pPlayer->nickname = "Ghost";
pPlayer->health = 100;

cout << "Здоров'я: " << pPlayer->health << endl;

delete pPlayer; // Не забуваємо звільняти пам'ять!
pPlayer = nullptr;
```

> **Золоте правило доступу:** 
>
>   * Якщо у вас є **об'єкт** структури (напр., `Player p1;`) — використовуйте **крапку (`.`)**.
>   * Якщо у вас є **вказівник** на структуру (напр., `Player* p1;`) — використовуйте **стрілку (`->`)**.

## 5\. `struct` vs `class` (Погляд у майбутнє)

У C++ `struct` та `class` є *майже* ідентичними.

**Єдина різниця:** 

  * У `struct` всі члени за замовчуванням **`public`** (доступні ззовні).
  * У `class` всі члени за замовчуванням **`private`** (приховані, доступні лише всередині).

**Угода:**

  * Використовуйте `struct` для простих "контейнерів" даних, де вся інформація відкрита.
  * Використовуйте `class` для повноцінного ООП, де ви хочете приховати внутрішню реалізацію (інкапсуляція).

## 6\. `typedef`: C-стиль для псевдонімів

`typedef` — це старий (успадкований з C) спосіб дати типу новий, коротший псевдонім.

```cpp
// Створює псевдонім 'String' для типу 'std::string'
typedef std::string String;

// Створює псевдонім 'ptr_to_char' для типу 'char*'
typedef char* ptr_to_char; 

String name = "Vitalii";
ptr_to_char c = "test";
```

Раніше в C `struct` вимагав писати `struct Player p1;`. `typedef` дозволяв скоротити це до `Player p1;`, що було дуже зручно . У сучасному C++ це вже не потрібно, але ви часто будете бачити `typedef` у старому коді.

## 7\. Перелічення (`enum`)

**Проблема:** У коді часто виникають "магічні числа".

```cpp
int playerState = 2; // Що означає '2'? Атакує? Захищається? Мертвий?

if (playerState == 0) { /* ... */ }
else if (playerState == 1) { /* ... */ }
```

**Рішення:** **`enum` (Enumeration)** — це користувацький тип, що складається з набору іменованих **цілочисельних констант**.

```cpp
// Оголошуємо "креслення" для станів
enum PlayerState {
    IDLE,      // = 0
    ATTACKING, // = 1
    DEFENDING, // = 2
    DEAD       // = 3
};

// Тепер код стає читабельним:
PlayerState state = DEFENDING;

if (state == IDLE) { /* ... */ }
else if (state == ATTACKING) { /* ... */ }
```

Внутрішньо `enum` — це просто `int`. За замовчуванням нумерація йде з 0, але ви можете задати її вручну:

```cpp
enum ErrorCode {
    OK = 0,
    NOT_FOUND = 404,
    SERVER_ERROR = 500
}; 
```

## 8\. Динамічні структури (Тизер)

Якщо поєднати `struct` та вказівники, ми можемо створювати **динамічні структури даних**.

Наприклад, "зв'язний список" — це ланцюжок структур, де кожна вказує на наступну.

```cpp
struct Node {
    int data;       // Дані
    Node* next;     // Вказівник на наступний такий самий 'Node'
};
```

 

Це дозволяє створювати списки, які можуть рости або зменшуватися під час виконання програми. Це основа для більш складних структур, як-от дерева та графи, які ви будете вивчати у курсі "Алгоритми та структури даних".

## 9\. Контрольні питання

1.  **Концепція.** Яку проблему "паралельних масивів" (напр., `nicknames[]` та `scores[]`) вирішує `struct`?
2.  **Синтаксис.** Опишіть (напишіть код) `struct` на ім'я `Drone`, яка має два члени: `string model` та `double batteryPercent`.
3.  **Доступ.** У вас є `Drone myDrone;` та `Drone* pDrone = new Drone();`. Як присвоїти `100.0` члену `batteryPercent` в **обох** випадках?
4.  **`struct` vs `class`.** У чому *єдина* технічна різниця між `struct` та `class` у C++? 
5.  **`enum`.** Навіщо використовувати `enum` (напр., `PlayerState::ATTACKING`) замість звичайних `int` (напр., `1`) для позначення станів?

<details markdown="1">
<summary>Натисніть, щоб побачити відповіді</summary>

**1. Проблема:**
`struct` вирішує проблему **організації даних**. Замість того, щоб тримати пов'язані дані (як нікнейм та рахунок гравця) у різних, не пов'язаних масивах, `struct` "пакує" їх в єдиний, логічний користувацький тип (`struct Player`), що робить код чистішим та безпечнішим.

**2. Синтаксис `Drone`:**

```cpp
struct Drone {
    std::string model;
    double batteryPercent;
};
```

**3. Доступ (крапка vs стрілка):**

```cpp
// 1. Для об'єкта
myDrone.batteryPercent = 100.0; // Використовуємо оператор "крапка" (.) 

// 2. Для вказівника
pDrone->batteryPercent = 100.0; // Використовуємо оператор "стрілка" (->) 
```

**4. `struct` vs `class`:**
За замовчуванням, члени `struct` є **`public`** (відкритими), а члени `class` — **`private`** (прихованими).

**5. `enum` vs `int`:**
**Читабельність та безпека.** `enum` робить код самодокументованим. `if (state == ATTACKING)` набагато зрозуміліше, ніж `if (state == 1)`. Це також запобігає помилкам, коли хтось випадково присвоює недійсне значення (наприклад, `state = 10`, тоді як `enum` дозволяє лише 0, 1, 2, 3).

</details>
